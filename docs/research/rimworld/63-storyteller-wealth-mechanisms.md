# 财富、市值、叙事节奏与袭击预算

本章补全[第04章](04-wealth-storyteller-trade.md)的估值、物理资产归属、开局与常规事件节奏，并给出 v20 体素项目的映射边界。依据本地 **RimWorld 1.7.4980 rev60** 的 Core XML 与托管程序集静态派生代码。程序集为 `.NETCoreApp v10.0`；这里不称其为 Unity Mono 目标。本文的数值复算没有执行原版代码，原版窗口/存档观察另列于第64章，项目集成实测另列于后续验证报告。

证据入口：[类型与哈希](evidence/storyteller-manifest.json)、[20条结论账本](evidence/storyteller-claims.json)、[149条XML及完整父链](evidence/storyteller-xml.json)、[数值与47项估值](evidence/storyteller-data.json)、[71个独立算例](evidence/storyteller-cases.json)、[验证结果](evidence/storyteller-validation.json)。下文 `STxx` 对应结论账本；`类型:行号` 是各 manifest 指定的本地派生文件行号，不是原始源码行号。所有完整派生代码仅保存在忽略目录 `.local-research/`。

## 1. 玩家看到的资产与事件强度

财富同时影响两类体验：把原材料转成装备、家具可增加资产价值；财富与人口又会提高事件预算。两者之间还有建筑折半、身体状况、难度、适应值及开局保护，不能简单写成“银币总数决定敌人数”。[ST04、ST09–ST12]

| 量 | 本版本普通玩家基地规则 |
|---|---|
| 物品财富 I | 地面、玩家携带/穿戴、合格持有者中的物品，按每件当前市场价 × 数量 |
| 建筑财富 B | 玩家人工建筑的 `MarketValueIgnoreHp`，加地板/基础层等 |
| 人物财富 P | 玩家 Pawn 市场价；排除任务临时住客，奴隶贡献 ×0.75 |
| 显示总财富 | `I + B + P` |
| 叙事者使用的财富 W | **`I + 0.5B + P`** |
| 事件基础点数 | 财富点 + 另计的人口点，再应用适应、难度、开局时间与上下限 |
| 袭击预算 | 事件点数再经派系、到达方式、策略、年龄、地图层等分支 |

贸易卖价还需买卖价差、难度、谈判和商品等修正，见第04章。这里的 `MarketValue` 不能当作直接卖给商人的银币收入。非基地、固定财富模式、商队和 pocket map 各有路径，本项目尚未覆盖。

## 2. 原版如何给一个物品定价

### 2.1 材料与工作量

有显式 `statBases/MarketValue` 时优先使用；没有时，所选可制作物的直接成本路径为：[ST01]

```text
材料价 = Σ costList数量 × 对应材料基价
       + costStuffCount / stuff.VolumePerUnit × stuff市场价
work = max(最终WorkToMake, 最终WorkToBuild)
未修饰基价 = 材料价 + (work > 2 ? work × 0.0036 : 0)
```

原版另有固定原料 RecipeDef 回退，并按配方首产品数量分摊。本章的自动估值只覆盖47个选定定义的显式市值和直接成本，未实现完整配方检索器。未指定 Stuff 的抽象查询采用每份2的猜价，因此表格必须写清材料。

材料对工作属性的顺序为 `base × stuffFactor + stuffOffset`。工作属性在**超过300时**先四舍六入五成双到最近5，再用于市场价。市场价自己的舍入在后面单独进行，二者不能混在一起。

来源：`storyteller/RimWorld.StatWorker_MarketValue:14–121`，`housing/RimWorld.StatWorker:299–315,798–834`；原始 `Stats_Basics_General.xml:43–108,151–163`、`Stats_Building_Special.xml:4–16`。这里以及后文的 XML 路径均相对游戏安装目录 `Data/Core/Defs/`。

### 2.2 品质、耐久、污损及舍入

| 品质 | 基价倍率 | 正向增值上限 |
|---|---:|---:|
| Awful | 0.5 | 不适用 |
| Poor | 0.75 | 不适用 |
| Normal | 1 | 不适用 |
| Good | 1.25 | 500 |
| Excellent | 1.5 | 1,000 |
| Masterwork | 2.5 | 2,000 |
| Legendary | 5 | 3,000 |

品质后的值为 `base + min(base × (倍率−1), 正向增值上限)`。例如4000基价传奇物品为7000，再乘其他修正，不是20000。没有 CompQuality 的木棒不走品质加价。[ST02、ST19]

耐久价格曲线为 `(0,0)、(0.5,0.1)、(0.6,0.5)、(0.9,1)`，点间线性插值，端点外钳制。50%耐久只值正常价格的10%，90%以上已是满价。此部件要求具体物品存在、`useHitPoints` 且 `healthAffectsPrice`，`MarketValueIgnoreHp` 不含该部件。[ST02]

其他重要修正：[ST03]

- 生物编码的相关装备市场价为 **0**。
- 曾被尸体穿着的服装市值 ×0.1。
- 非新鲜尸体自身市值为0；新鲜尸体基价来自基础屠宰产出价 ×0.6，不是死者生前市值。

按 StatParts 顺序变换，再应用后处理和 Scenario，最后仅在绝对值**严格大于200**时取最近5，使用 Unity 的 ties-to-even；市值默认不再普遍取整数。例：202.5→200，207.5→210，63.48仍为63.48。钢长剑未舍入基价254.8、Normal满耐久最终255，但60%耐久应得到127.4；不能先拿255乘0.5算成127.5。[ST01–ST03]

## 3. 搬运、建设、制作和死亡后的财富去向

原版递归查询 `HaulableEver`，检查物品或父容器已生成、根位置不在迷雾内。终点累加没有逐件检查“玩家所有”，所以地上尚未搬入仓库的可见物品也可计入。经过的飞船、MapComponent、非玩家 Pawn、任务临时住客等容器被过滤。不能仅用“仓库库存总数”代替物品财富。[ST05]

| 状态变化 | 原版计价边界 |
|---|---|
| 地面→玩家携带→普通储存容器 | 同一实体移动，不应重复或遗漏 |
| 材料送到 Frame | Frame 有 `resourceContainer`，材料仍计入 I |
| 未完成建筑框架自身 | 普通生成Frame缺少成本/工作定义，自身0；特殊difficulty成本分支需另审 |
| 材料变为 UnfinishedThing | 所选Core未完成品自身无成本/工作价；ingredients为普通List，不是IThingHolder，不自动递归再算原料 |
| 完工建筑 | 消耗材料，增加建筑市场价；叙事W中的建筑部分再折半 |
| 原料投入 Refuelable | 实物拆分并销毁，转为fuel浮点；已装燃料不额外计价 |
| 燃料被排出成物品 | 新实物重新进入物品口径 |
| 玩家死亡 | 活体P移除；尸体自身走屠宰产出价格，遗留装备可继续计入I |
| 敌方身上的装备 | 仍由敌Pawn持有时被过滤；落地后按普通可见物品规则处理 |

`allowUnreal=false` 会跳过尸体直接持有的内层Pawn，但仍递归其子持有者。因此不能把“尸体内层Pawn不计价”推断成“所有尸体装备都不计价”。尸衣污损和尸体自身腐败也不是同一个价格条件。

顶层地板需要非迷雾；foundation grid在本函数中独立加算，未复用同一个迷雾判定。天然建筑、敌方建筑、建筑蓝图与已完成玩家人工建筑亦不能混为一类。参见 `economy/RimWorld.WealthWatcher:115–261`、`storyteller/Verse.ThingOwnerUtility:304–384`。[ST04–ST06]

## 4. 人物市值与健康人口点

### 4.1 SummaryHealth

```text
活体SummaryHealth = clamp(Π(1 − min(每项impact,0.95)), 0.05, 1)
死人SummaryHealth = 0
```

非永久、可见伤口的 `impact = severity / (75 × HealthScale)`。缺失部位按共同祖先去重，只让符合 `IsFreshNonSolidExtremity` 且有部位标签/子部位/出血等资格的缺失项贡献 `part.hitPoints/(75×HealthScale)`。例如两处15严重度、成人比例1的普通伤口得到 `0.8×0.8=0.64`，不是0.6。旧残肢不继续直接扣这一综合健康值，但仍能严重影响能力。[ST08]

普通疾病的基础 impact 是0，感染、失血等可以通过能力和疼痛降低人物市值，却不必直接降低 SummaryHealth。这一值用于叙事人口点；不能把 `Consciousness` 或所有能力平均值拿来替代。

### 4.2 人物市场价

原版人形价因子的主干为：[ST09]

```text
factor = (0.2 + 0.8×SummaryHealth)
       × Π(capable ? lerp(0.5,1,forTradePrice容量) : 0.6)
       × averageSkillCurve(全部技能平均值)
       × lifeStage.marketValueFactor
factor += 未压制trait价值偏移 + Beauty×0.2
人物未最终修饰价 = 1750×max(0.1,factor) + Hediff价格偏移
```

技能均值曲线是 `(0,.2)、(5.5,1)、(20,3)`。原版遍历所有 PawnCapacityDef，本地Core选中11种；12技能平均包含当前项目没有的技能。健康、所有能力1、均值5.5的成人基准为1750；全技能0但其他正常则为350。

能力判断有两个读数：`CapableOf` 使用当前真实能力；可用时再计算 `forTradePrice=true` 的容量。后者跳过 `priceImpact=false` 的直接 Hediff `CapMods`，但 worker 仍可能读取当前疼痛、其他依赖能力和是否清醒。故“暂时疾病完全不影响售价”和“所有当前能力直接相乘”都不准确。

Biotech的物品市场价部件还可施加生物年龄曲线 `(3,.5)、(13,.9)、(18,1)`。当前项目使用成人基线、现有9技能、11能力、无traits/植入物/儿童，此为明确子集，不补造缺失技能数值。

## 5. 财富怎样变成威胁点

以下为普通玩家基地、成年自由殖民者的选定主干。曲线点间线性插值，范围外取端点。[ST10]

| W | 财富点曲线 | 每殖民者基础点曲线 |
|---:|---:|---:|
| 0 | 0 | 15 |
| 10,000 | 0 | 15 |
| 14,000 | 0 | 在10k–400k间插值 |
| 400,000 | 2400 | 140 |
| 700,000 | 3600 | 在400k–1m间插值 |
| 1,000,000 | 4200 | 200 |

```text
W = I + 0.5B + P
人口点 = Σ 每人基础点(W) × (0.35 + 0.65×SummaryHealth)
adaptFactor = 1 + adaptationEffect × (adaptCurve(adaptDays) − 1)
raw = (财富点 + 人口点) × 1 × adaptFactor × threatScale × settleFactor
事件点 = clamp(raw, GlobalPointsMin(), 10000)
```

地图随机因子在该普通 Map 路径为1。Randy的额外随机是事件参数生成中的另一步，不能混进所有叙事者的公式。半健康殖民者仍保留67.5%人口点。

`settleFactor` 为 `(10日,.7)、(40日,1)`，输入是**整数** `DaysPassedSinceSettle`。GlobalMin却用浮点日数决定抽样上界：12日前固定35，12–35日向难度上界线性增长，之后上界保持。每次以 `TicksGame/2500` 为原版确定性随机种子，在35和该上界之间抽取。于是20.9日的settleFactor为0.8，但最低点上界已按20.9日推进。

算例：I=20000、B=20000、P=6000，3名健康成人，Rough适应影响.9、适应值0、定居第10日：

```text
W = 36000
财富点 = 22000 / 386000 × 2400 = 136.787565
人口点 = 3 × (15 + 26000/390000×125) = 70
适应混合 = 1 + .9×(.8−1) = .82
raw = (136.787565+70)×.82×.7 = 118.696062
```

原版动物、机械体、任务住客、奴隶、儿童、低温休眠和非基地目标另有修正；这里没有删去原版这些机制，也没有声称项目已经实现。

## 6. 难度与受挫后的恢复

| DifficultyDef | 威胁倍率 | 适应影响 | 正值增长倍率 | 最低点上界 | 大威胁/开局威胁 |
|---|---:|---:|---:|---:|---|
| Peaceful | 0.1 | 1 | 0 | 45 | 关闭 |
| Easy | 0.3 | 1 | 0.25 | 45 | 开启 |
| Medium | 0.6 | 1 | 0.75 | 70 | 开启 |
| Rough | 1 | 0.9 | 1 | 70 | 开启 |
| Hard | 1.55 | 0.7 | 1 | 70 | 开启 |
| Extreme | 2.2 | 0.4 | 1 | 70 | 开启 |

未声明的字段需结合类默认值；最低点上界未填为0时，`Difficulty.PostLoad` 把小于35的值修正到70。不能直接把XML缺项当成0。[ST12]

适应值初始0，范围−60至100。原版每30000ticks，即半日，增加 `0.5×growthCurve(value)`。非负时前30日暂停增长；负值在宽限期也能恢复。仅在**当前值严格大于0**时乘难度的正值增长倍率，因此Peaceful在第30日可从0增长到.5，之后正值增长倍率0才阻止继续增长。[ST11]

| 曲线 | 控制点 |
|---|---|
| 威胁适应因子 | `(-30,.4),(0,.8),(30,1),(60,1.2),(120,1.6),(180,2)` |
| 每日增长 | `(-30.01,6),(-30,3),(-.01,3),(0,1),(59.99,1),(60,.5),(119.99,.5),(120,.25)` |
| 暴力倒地损失：人口→适应日 | `(1,8),(2,6),(3,6),(11,5),(20,3.5)` |
| 失去人物损失：事后人口→适应日 | `(0,30),(11,30),(20,20)` |

外部暴力倒地先入当tick队列；同tick失去该人物会移除其待处理倒地，再扣一次失去损失。倒地使用当前人口，失去使用 `Population−1`；不能在项目先移除人物后又对已减少的人口减1。非外部暴力倒地不走相同损失。原始因子曲线有180=2，实际适应上限100使raw因子最多约1.466667，再经难度影响混合。

## 7. 三位叙事者如何安排事件

### 7.1 Cassandra与Phoebe

| 常规大威胁参数 | Cassandra | Phoebe |
|---|---:|---:|
| 最早普通周期 | 11日 | 13日 |
| on窗口 | 4.6日 | 8日 |
| off窗口 | 6日 | 8日 |
| 同类事件最短间距 | 1.9日 | 默认0 |
| 每on周期事件数 | 随机1–2 | 1 |
| 强制选RaidEnemy的早期范围 | 20日前 | 20日前 |

周期每1000source ticks检查一次，一日60个interval。天数经 `RoundToInt(days×60)` 变为interval。先抽事件数和位置，排序后松弛间距；本版本后续项移动用 `values[i]+j`，不是通常猜想的 `values[i]+j−i`。尾项允许 `<=onEnd`，所以恰好在第一个off间隔的事件可以成立。不能看见off阶段就额外抹掉这个已排定事件。[ST13]

原版重放此前周期以获取上一事件，并用世界、目标、comp索引、周期播种；`acceptFraction<1` 会shuffle再截断，不重新排序。最多101次排位尝试，超过后先清空再退出。Cassandra的6日off已大于1.9日间距，项目独立求当前周期不会因上一周期最后一次事件违反该间距；这是该参数组的性质，不是任意叙事者都可使用的优化。

### 7.2 ClassicIntro独立开局事件

| 全局interval | source游戏日 | 事件 |
|---:|---:|---|
| 150 | 2.5 | 访客，40–100点 |
| 204 | 3.4 | 小威胁或misc |
| 264 | 4.4 | misc |
| 324 | 5.4 | RaidEnemy，40点 |

这解释了“常规周期11日才开始，但更早有首袭击”。Intro只在精确边界触发，晚加入或错过边界不补发。[ST14]

首袭击的 `raidForceOneDowned` 给首名Pawn设置 `health.forceDowned`、可招募和禁止个体逃跑。这里的forceDowned让该人到倒地判定时跳过随机“倒地即死”，**不会使刚生成的敌人立刻倒地**。重要器官损毁等 `ShouldBeDead` 分支在此前执行，仍可致死。另有 `raidNeverFleeIndividual` 标记，不能据此推断整个群体永不撤退。

### 7.3 Randy

Randy先在1000ticks检查中以MTB1.35日决定是否产生事件机会；成功后才选类别。类别权重为Misc3.5、大威胁1.4、轨道访客1.1、派系来访2.4、小威胁.6、飞船碎片.22。距上次大威胁严格超过13日时优先选大威胁类别，但仍需先过MTB，因此不是“第13日保底发生袭击”。生成基础点数并夹取后，再乘随机0.5–1.5。[ST15]

该表只说明核心分支，不包含全部疾病、任务、派系援助、DLC内容、每种事件的资格过滤和权重曲线。

## 8. 从威胁点到敌方队伍

原版先解析派系、策略、到达与年龄，随后调整袭击点：[ST16]

```text
p1 = points × arrivalCurve(points)
p2 = p1 × strategyCurve(p1)
budget = max(p2 × ageFactor × layerFactor,
             strategy.MinimumPoints × 1.05)
```

策略必须用已受arrival修正的p1求值，不能两个曲线都使用初始points。ImmediateAttack默认 `minPawns=1`；海盗最便宜Drifter为35，因此最低调整预算36.75。

选择队伍前还先选择 `PawnGroupMaker`。Pirate主Combat组commonality100，此外有近战30、远程20、爆破15、狙击10、纯流浪者2.5等组；项目只做主组的三个低阶单位，未完整复刻这些组的混合分布。[ST17]

```text
最大单Pawn成本 = min(factionMaxCostCurve(budget), budget/minPawns)
最大单Pawn成本 = max(上述结果, factionMin×1.2, strategyAllowedMin×1.2)
```

海盗单人上限曲线为 `(0,35),(70,50),(700,100),(1300,150),(100000,10000)`。最低预算36.75下上限经保底为42，但剩余预算仍单独过滤，所以不会生成50点单位。

逐个选择时，过滤剩余预算、单人上限、策略、领袖和每组限制等；权重为 `selectionWeight × curve(cost/highestCost)`，曲线 `(0.2,.01),(0.3,.3),(0.5,1)`。`highestCost` 是本次组队循环历史上出现过的最高合格成本，下一轮不重置。选中后扣成本，没有选项时退出，人数不是固定波次常数。

### 8.1 当前低阶单位与武器池

| PawnKind | 战斗成本 | 主组基础权重 | 武器预算 | 品质中心 | 装备HP抽样 |
|---|---:|---:|---|---|---|
| Drifter | 35 | 10 | 60–200 | Poor | .2–.6 |
| Thrasher | 50 | 3 | 100–160 | Poor | .4–1.1 |
| Scavenger | 50 | 10 | 200–300 | Poor | .4–1.1 |

原始定义位置：`PawnKindDefs_Humanlikes/PawnKinds_Pirate.xml:15–48,79–106`，另含父定义继承。武器预算先按**Normal、满耐久的抽象最终价格**筛选，再抽装备品质和HP。[ST18–ST19]

- Drifter：在项目武器子集中木棒可用；预算达到63.48才加入钢匕首。
- Thrasher：木棒/钢匕首可用；钢长剑255超过其最高预算160。
- Scavenger：左轮135.4可用；预算达到220加入冲锋手枪。
- 冲锋手枪子定义的 `ShortShots` 标签会追加到父 `Gun`，不能因只读子节点而把它从Gun池中删掉。原始 `Weapons/BaseWeapons.xml:86–96` 与 `Weapons/RangedIndustrial.xml:173–243`。

原版pair权重为 `Commonality×Price×Ideo×Xenotype`，Commonality还有武器/材质生成权重及全材质归一化。项目每种武器只选一个材质，把该子集中每种武器总commonality重新归一化为1，因此表现为按价格加权；这不表示原版wood/steel材料pair天然就是1。

默认装备品质不是固定Poor：随机值 `<.1` 取中心−1，`[.1,.2)`取中心+1，其余中心，最后夹到允许品质范围。当前三类低阶单位因而为Awful10% / Normal10% / Poor80%，除非forceNormal、forceWeapon、特定衣物要求或爵位等覆盖。木棒无CompQuality，保持无品质语义。

随后HP抽样 `<1` 时得到 `max(1,RoundToInt(roll×MaxHP))`，`>=1` 时保持满耐久。例如52.5取52、53.5取54。Scavenger与Thrasher的上界1.1自然产生一段满耐久概率，而不是允许110%HP。
