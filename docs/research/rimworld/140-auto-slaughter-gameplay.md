# v48：自动宰杀与种群配额

本轮把已有的饲养、繁殖、现场宰杀和尸体加工接成可持续管理的循环。玩家为兔与鹿设置保留上限，系统从实际家畜中筛选超额个体；开启「饲养」分工的殖民者实际靠近并完成劳动，产生唯一身份的尸体，后续由「烹饪」分工搬到屠宰点加工。原版依据见 [139 静态机制](139-auto-slaughter-mechanisms.md)。成本、时间和生产效率继续使用集中参数，未做平衡校准。

## 玩家操作与规则

打开「动物与饲养 → 自动宰杀」。每个物种有总数、成年雄性、成年雌性、幼年雄性、幼年雌性五项上限；幼年包含幼崽。留空为不限，0 表示不保留该类可宰杀个体。输入只是草稿，点击「应用配额」才改变模拟；重置为不限也需要应用。默认全部不限，升级旧营地不会自动减少动物。

所有配额都是上限，并非繁殖所需的最低数量。系统按成年雌、幼雌、成年雄、幼雄、总数依次筛选；已经选中的个体不重复扣减。总数上限仍可进一步减少各类数量。各组优先年长个体，同龄使用稳定身份顺序。

怀孕动物默认受保护，既不被选中，也不计入可宰杀配额；界面分别显示实际存活数量、受保护数量和有效计数。开启允许宰杀孕兽后，它们计入配额，在相应的成年雌或总候选池中排在非孕个体之后，孕进度较大的先被选择。这是每个池内部的顺序；成年雌配额仍先于雄性配额处理。

自动待宰是派生名单，手动待宰仍是独立指令。取消手动标记不会解除仍然超额的自动资格；调高配额也不会清除手动标记。手动指令可以宰杀被自动规则保护的孕兽。Web 将明确待放归的个体在配额计算前排除，视为即将离群；原版仍计入候选，最后在工作资格处否决放生目标，这处差异明确保留。

## 现场工作、打断与保存

自动工作使用现有的动物预约、接近路径和相邻互动阶段，不会通过远程扣数量完成。两个饲养员不能同时处理同一只动物。关闭饲养分工、征召、人物状态变化、不可达通路或允许区域限制，都会阻止或中断工作。完成前不产生尸体，也不计入物资生产。

修改配额会立即撤销失去资格的自动任务。出生、成长、受孕、死亡与归属变化会在后续处理前重新计算资格；保存后加载也先重算。仍有资格的任务保留接近阶段、路径与已完成互动进度，失去资格的任务被释放。自动任务不会改写动物的手动待宰标记，也不会伪造材料、肉或食物。

模型和渲染继续分离。动物详情与列表显示手动/自动来源、当前饲养员和互动阶段；自动宰杀沿用实际宰杀阶段的持刀动作。本轮只校验渲染代码和生产构建，未进行视觉或浏览器交互验收。

存档升级为 **v48**，只增加每物种策略与 `handleTask.action = autoSlaughter`。候选身份和配额统计不作为权威状态保存。v1–47 迁移补充全部不限的默认策略，保留原有动物、怀孕、手动指令、工作进度和资源账本；旧版标签中夹带新策略或自动任务会被拒绝。当前版拒绝缺失、负值、小数、超容量或未知字段的策略。

## 验证与证据边界

- 静态提取与再校验：18 个类型、69 个锚点、10 项有界检查、4 项 XML 投影。源码为本地 DLL 的派生反编译结果，不是原始工程或实机观察。
- 控制夹具测试覆盖分类/总额叠加、老幼、孕期保护和排序、放归优先、独立手动指令、实际工作、打断、多人预约、防重复产物和严格迁移。UI 测试使用 React 服务端渲染与输入解析，没有启动浏览器。
- 原始 v47 检查点从确切提交生成，只有公开玩家命令。升级后的默认策略与旧模型逐 tick 对照，保留 8 只动物、待驯服标记、已有施工损失和活动框架；详情见 [迁移来源](evidence/auto-slaughter-v47-provenance.json)。
- 普通经营验证沿用已存证的 v29 自然出生检查点，再由当前模型通过公开命令继续；历史生成过程与本轮继续运行分开记录，不能声称本轮从新营地重跑了整个繁殖过程。

本轮最终结果和文件哈希记录于 [冻结验证摘要](evidence/auto-slaughter-voxel-validation.json)。所有测试在本地执行，GitHub Pages 仍只安装依赖、构建和部署。遵照用户要求，没有启动或操作原版、浏览器、预览或 GUI；线上核验只比较 HTTP 发布字节。

最终合并结果为 **124 个文件、1,654 项通过、零跳过**。首次全量运行有两项原有建墙取消用例失败，报告仅保留 `STACK_TRACE_ERROR`，耗时分别约 5.46/6.35 秒，不能仅据此确定失败原因；随后未修改实现、断言或超时，原样串行重跑整个 `voxel.test.ts`，15 项全部通过。冻结摘要保留两次报告，并逐文件使用最新完整结果。`npm run build` 中的 TypeScript 检查与 Vite 构建通过；仍有既有的大于 500 kB bundle 提示。

普通经营续行通过 **17 项检查、683 tick 逐 tick 守恒核对**，从 tick 132014 运行至 132697。自然出生的幼雌 1592 被幼雌配额选中，饲养员实际步行；在 25/100 工作进度存读后取消，40 tick 内没有死亡或伤害，再恢复并于 40/100 进度存读，最终完成一次宰杀。原身份关联的尸体经真实搬运和加工，消费 1 具尸体、产出 18 单位肉；完成后再次存读并运行 60 tick 没有重复产出。父母动物 475/477 和三名殖民者全部保留。产肉仍沿用现有简化参数，本轮没有校准年龄与肉量的平衡。

独立 v47 迁移对照运行 **109 tick**，在 117、156、196 tick 重载，220 tick 完成此前的椅子框架。每一步物理状态与旧代码一致；最终 8 只动物及待驯服标记保留，木材账目为地面 67 + 施工消耗 15 + 旧档已有失误损失 8 = 90。

## 仍未实现

动物 Bond、完整身体伤情、运输群体/卸货状态、训练、畜产品及完整自动宰杀专属原版界面仍未实现。Web 成年判定沿用现有可繁殖成长阶段，重新派生名单代替原版有特定失效入口的缓存。这里补齐的是现有兔/鹿饲养管理机制，不代表完整畜牧系统或完整 RimWorld 已完成。
