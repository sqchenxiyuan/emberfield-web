# v45：物品禁止／允许与经营作业

更新：2026-11-04。本轮继续优先搭好玩法机制，工时、容量和经济数值沿用暂定设置。原版依据是[132静态机制](132-item-forbidden-mechanisms.md)，不是实机对照结论。

用户要求暂停运行程序交互后，没有启动本轮浏览器验证，也没有继续原版操作。以下实现经过无界面的模型测试及构建；**不能据此称界面、主线程渲染或 Worker 渲染已实际验收**。原版仅保留中止前准备记录，见[134验证边界](134-native-item-forbidden-runtime.md)。

## 玩家操作

1. 选择地面物品或货架中的某一堆，在信息面板切换“禁止取用／允许取用”。每堆独立保存状态。
2. 使用“禁止物品／允许物品”工具，在当前工作层拖出矩形，一次处理范围内已探索的地面堆，包括货架同格的全部堆。不同楼层和未发现物品不会被修改。
3. 被禁止的地面物品显示红叉。库存仍包含这些物资；若工人无法取料，可以解除禁止，或提供另一处允许取用的来源。
4. 明确安排人物装备武器或穿戴衣物会解除该物品的禁止，并允许这次装备任务走出允许区域。家具重装仍需先允许取用原家具。

工具复用当前工作层的平面拾取；物品标记沿用已有货架堆放高度和探索过滤。界面布局和遮挡尚未通过本轮交互检查。

## 与已有系统的连接

| 情况 | 本版行为 |
|---|---|
| 普通搬运、施工、生产、燃料补给 | 地面材料选择排除禁止物；途中禁止使受影响的取料计划释放预约并重新安排 |
| 吃饭、药物、代喂患者和囚犯 | 按实际取料居民筛选地面来源；禁药仍可按已有政策进行无药护理 |
| 驯养、维护驯顺和人工喂养 | 驯养员不拿禁止饲料，走到来源前也重新检查 |
| 正常家畜自主饥饿 | 不吃禁止地面物品；目标途中变禁止时重新寻找食物；草和站立作物继续用原有规则 |
| 野生动物、普通囚犯自主吃饭 | 保留各自既有可达、食物和牢房约束，不套用居民物品旗标限制 |
| 未完成品 | 禁止后暂停续作，保留作者、原料、身份和进度；允许后原作者可恢复 |
| 已经拿走的材料／餐食 | 与剩余地面堆相互独立，禁止剩余堆不会追溯修改携带物或重复扣料 |
| 自动送入仓库 | 不主动合入禁止接收堆；禁止堆仍占空间，货架有空槽时可另放一堆 |
| 物理拆分／落地合堆 | 拆分继承旗标，真正合并时沿用接收堆旗标；旗标不等同于物理不兼容 |
| 库存、财富、做到目标数量 | 保留已有统计口径，不因禁止额外排除产品；禁止成品仍可满足生产目标 |
| 交易 | 满足既有位置、可达和商品条件的禁止货物与白银可交易；购回不统一清旗标，物理合堆沿用接收方 |

这里的“切换后立即释放受影响计划”是 Web 调度适配。原版 `CompForbiddable` setter 更新旗标及候选列表，不直接遍历取消全部作业，不能把 Web 的中断时机声称为原版逐 tick 复现。

普通家畜饥饿与原版 `EatRandom` 好奇进食是不同分支；本版未新增后者，也未新增原版所有精神状态、特殊派系或 Lord 的保留规则。禁止物品不阻塞通行，不是允许区域，也不是防止出售的锁定功能。

## 状态和兼容

- `Cargo.forbidden` 从旧版武器／未完成品扩展到所有独立物品堆。`itemForbidden` 和 `itemForbiddenArea` 是公开命令；旧武器和携带未完成品命令继续兼容。
- 通用来源查询、取料复查、用餐有效性和储存目的地共用现有物资预约体系，不另建一份“可用库存”实物数据。
- v45 校验旗标为布尔值，未完成品包内的原始材料也保留该字段。制作不会因原料曾禁止后又允许而失败。
- v1–v44 缺少通用旗标时沿用原物品，不凭空添旗标；旧武器和未完成品旗标保留。把 v45 的新物品字段只改版本号伪装成旧档会被拒绝。
- 旧档地形、水体、探索、物资、统计、区域和生产设置保留。普通作业在读档时仍按已有规则重新分配；不要求瞬时路径、预约和 owner 字段逐字不变。

## 本轮验证

`tests/voxel-item-forbidden.test.ts` 使用明确的受控地形／物资起点，通过公开命令和真实模拟 tick 覆盖：单堆和跨层边界、施工中断及守恒、来源和接收堆限制、货架多堆、吃饭和护理、制作及未完成品读档续作、目标库存、装备／穿戴例外、家具重装与严格迁移。

`tests/voxel-item-forbidden-hosts.test.ts` 覆盖驯养员取料的三类作业、来源中途禁用、释放预约、已经携带的饲料、狱卒代喂、家畜／野生动物对照，以及禁止货物、付款白银和购回旗标。

`scripts/voxel-item-forbidden-legacy-verify.mjs` 只读取上一版冻结清单中的六份原始 v44 存档（四个模型检查点、两个当时的浏览器导出文件），先核对旧 SHA-256，再在无界面模型中迁移和继续 20 tick。旧文件不重写；这不是新的浏览器验证。

全量本地回归、类型检查、构建及三项静态证据检查的具体结果见[冻结验收记录](evidence/item-forbidden-voxel-validation.json)。发布流水线继续只安装依赖、构建和部署，测试在本地运行。

最终覆盖 **119 个文件、1,573 项测试，0 跳过**。初次整套回归暴露未完成品原料字段白名单遗漏，以及两处仍把通用禁止旗标视为非法的旧断言；修复实现、保留非法类型拒绝并更新旧预期后，相关套件重跑通过。长时收获准备满足至少 8 游戏日和 90 份谷物，再完成后续食物测试；本轮 JSON 报告没有保留准备阶段的 console 行，不引用上一版的精确收获 tick 冒充本轮测量。构建通过，仍有现有的大包体积提示。

```powershell

npx vitest run tests/voxel-food.test.ts --maxWorkers=1 --testTimeout=30000
```

长时食物收获测试单独运行，保持原有真实生长、收获、烹饪和逐 tick 账本要求。冻结清单校验只是追溯记录，不替代重跑测试；加 `--local` 可复核本机原始日志、旧档和构建产物。历史浏览器脚本只更新了已变更按钮的定位，未执行，未改旧报告冒充本轮结果。
