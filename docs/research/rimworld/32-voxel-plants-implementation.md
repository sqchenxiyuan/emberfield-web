# 体素树木生长与林地经营

本章记录 Emberfield 多层体素分支的独立实现。原版静态与 XML 依据见 [第 30 章](30-plants-lifecycle-forestry-regrowth.md)，实际运行观察见 [第 31 章](31-native-plants-runtime.md)；本章的三维占用、通路保护、自然补生采样和确定性舍入是项目设计，不能当作原版逐 tick 等价复刻。

## 玩家操作

1. 选择「林地区」，从「种植树种」选择白杨、松树或巨柱仙人掌，再在露天空地划区。树位之间需留一格，土壤须满足该树种最低肥力。
2. 工人按「种植」分工执行，播种需要实际劳动；施工完成才出现树苗。三种树的研究与技能条件暂预先解锁，也允许跨生态种植。
3. 点击树木查看成长百分比、当前砍伐收益、年龄、健康、肥力、光照、温度和增长/停长原因。画面中的植株尺寸随成长变化。
4. 林地不会自动砍成熟树。通过「标记砍伐」或伐木工具决定采伐时机；砍完后林地会自动补植。
5. 取消林地保留活树并停止补植。清除幼苗没有木材；普通农田的擦除语义仍是清理作物且不收获。

## 参数和适配

| 树种 | 健康成熟木材 | 最低肥力 | 满速生长日 | 有产量的成长阈值 | 满龄日数 |
|---|---:|---:|---:|---:|---:|
| 白杨 | 27 | 0.7 | 15.05 | 严格大于 0.4 | 135.45 |
| 松树 | 27 | 0.7 | 20 | 严格大于 0.4 | 180 |
| 巨柱仙人掌 | 15 | 0.05 | 5 | 严格大于 0.2 | 200 |

「满速生长日」不是实际成熟所需日数。日夜、温度、肥力和遮光共同影响进度；本地一天为 12000 tick，仍用 20 TPS。普通树温度最佳区间为 6～42°C，在 0°C 及以下、58°C 及以上停长；巨柱仙人掌上限为 75°C。夜间休眠与本项目日照模型共同作用。

新地图初始成长为 `clamp(U(0.15,1.5))`；自然新苗初始 0.15，人工播种完成为 0.0001。地图初始树龄独立均匀分布在寿命之前，因此部分老树会比刚种的树更早衰老。成长超过最低阈值后的木材曲线从半产量逐步升到满产量，健康乘数为 `0.5+0.5×health`。取整使用种子与位置决定的固定舍入，因此同株满地等待不会反复抽取更高产量；这是对原版随机舍入的明确适配。

播种基准 4000 原版工作量换为 1334 项目 tick；伐木基准分别为 800/710/210，按 60→20 TPS 转为 267/237/70，再应用 `3.3−2.3×growth` 的幼苗工作倍率。人物技能、工具品质和部分原版属性尚未接入。树桩系统尚未实现，砍伐直接移除树实体。

树龄与连续缺光时间会保存。超寿命或长期缺光引起渐进健康损失，多个原因不重复叠加；死亡移除树木且不凭空产木。伤害采用连续近似，原版使用较低频率批次和取整。植物病害、火灾、季节落叶、草灌生态和完整生态竞争仍未实现。

## 多层和资源约束

树苗从种下时预留两格高度，视觉尺寸独立变化，避免长大时才把人物困住。种植和自然补生会检查地板、净空、光照、邻株间距与实际占用，仓储、农田、设施、梯子和施工位置受到保护。生成树苗前还检查活动路径、工位及其周围节点的连通性，独立缓冲区避免覆盖工人当前寻路结果。

自然更新每 200 项目 tick 抽查 16 个表层候选格，按采样间隔换算温带/寒带/沙漠的 20/25/35 日 MTB，结合本项目树木覆盖系数、肥力与上限；自然更新到总树数 768 时停止，所有树实体容量仍为 4096。概率由种子、tick 和样本序号决定，存档无需另存可变随机流。玩家林地区最多 512 个点，拖动框选会间隔安排并反馈跳过的格数。这是保守的三维适配，不保证被砍的位置固定多少日后复活；原版总野生植物密度不能直接拿来当树木密度。

砍伐继续使用有限物品堆与原子产出：没有合法落点就保留树和任务，腾出空间再继续。搬运、堆叠、仓储和木材账本沿用现有机制。

## 存档

v9 保存成长、年龄、健康、缺光时间、人工种植标记、林地区及生态续跑状态。v8 及更早存档加载时保留原有地形和树木数量，把旧树迁为健康成熟状态；旧在途伐木作业保留旧工作量，之后新发出的命令使用新规则。不会按新的地图生成器重新生成已有世界。

真实发布版本 `ab51596c983082b7b2db2aef8da965018833f25b` 的 v8 fixture 在修改前捕获，字节 SHA-256 为 `e44adc4c30a85f9c58d38d78087c079a1694b0c58e14c62c28b2253820be0512`，不能用新版模拟器重建并冒称旧档。

## 验证入口

```powershell
npm test -- --silent
npm run test:voxel:plants
npm run build
npm run test:voxel:plants:browser
```

正常流程测试从新生成地图开始，用公开命令安排农田、灶台、仓储和林地，让实际日夜推进至树木成熟，再采伐、补植、取消区域与清除幼苗。不会注入木材、成长值、食物需求或时间。浏览器测试通过文件选择器载入这条正常流程产生的存档，在 Worker 与主线程渲染中实际点击树木与操作林地。

正常经营流程已完成 10 项检查，运行到 tick 170519（14.21 游戏日）：人工植株从 0.0001 成长到 1，成熟采伐得到 15 木材，自动补植并验证幼苗清除零产出；观察到 7 株自然新苗与 14 株老树死亡。160 格稻米供给下完成 41 份简餐，其中 35 份被食用，最低饱食度约 12.95。木材、食材、餐食和腐坏账本闭合。

浏览器 Worker 和主线程路径各完成 11 项检查，包含真实 v8 导入、苗木检查、取消林地、清除苗木、实际种植、成熟采伐、自动补植、手动存取及 900×700 操作。既有三层施工、供粮、住房、电力、保鲜、物流、切石和三个生态区开局回归也通过。

最终全量 **314/314** 单元测试通过，其中新增植被测试 **23** 项，覆盖通路保护、满地原子产出、成长曲线、环境边界、老化、自然更新确定性和真实旧档迁移。第一次并发全量中的整日模拟用例触发默认超时；单独复查通过，将这个有界整日模拟的测试时间限额提高至 30 秒后，全量用两名测试 worker 重跑通过，没有跳过断言或缩短游戏时间。

同一页面六轮保存→新世界→读取均通过，恢复后保持 27 个几何体、4 张纹理、16 个区块，地形缓冲区均为 2,008,968 字节。这只覆盖跟踪到的渲染资源，不代表浏览器/GPU 总内存，也不是长期泄漏或 4 GiB 极限测试。

完整记录冻结在 [voxel-plants-validation.json](evidence/voxel-plants-validation.json)，由 `scripts/research/record-voxel-plants-validation.mjs` 核对报告、产物和图片哈希后产生。可用 `scripts/research/verify-voxel-plants-validation.mjs` 复核快照和真实 v8 fixture；历史源码/构建哈希表示当时身份，不要求后来版本字节不变。当前实现仍不是完整生态模拟，也不证明全生态区长期生存平衡或大地图性能。
