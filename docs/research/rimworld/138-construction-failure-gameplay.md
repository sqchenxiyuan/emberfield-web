# v47：施工能力、失误与重新施工

更新：2026-11-05。继续以玩法和机制为先：居民能力影响施工风险，失误造成实际材料损失，余料重新进入物流，再由普通施工完成建筑。基础概率、工时、成本和失误后的经济节奏仍可后续调整。原版静态依据见 [137](137-construction-failure-mechanisms.md)。

本轮不启动或操作原版、Web 页面、预览或截图。证据限于安装包静态解析、无界面模型测试、类型检查、构建和发布文件核对，不代表画面或游玩手感已经验收。

## 玩家能做什么

在人物技能面板查看当前「整项施工成功率」。它取决于建造技能、操作能力和视力，是以能力不变估算一项完整工程的成功率，不是每个 tick 都有那么大的失败概率。安排熟练或恢复健康的居民施工，可以降低材料损耗；货架和小货架也使用建造技能、施工速度并获得经验。

失败时提示施工者与损失的材料。剩余材料先放回附近地面，新蓝图从零进度开始，仍需要工人搬来完整成本的材料。缺料会等待，可以砍树、采矿或调整物品禁止/允许与人员分工后继续。取消重试蓝图走普通退款流程，不会补回已损失物资。

该机制始终适用于普通施工，**不依赖「自动重建家园建筑」开关或 Home 范围**。自动重建处理火毁等建筑损毁；施工失误自身保留重新建设的意图。没有添加隐藏的免费材料或保证下次成功。

## 工作与材料流

| 状态 | v47 行为 |
|---|---|
| 缺料、搬运、走路、休息、暂停或征召 | 不抽施工失败；普通中断保留工程进度和原料 |
| 收齐材料并在合法工作位置劳动 | 先学习，再按本次实际工作量累计风险；失败在本次进度写入前结算 |
| 正常完成 | 沿用完工者品质和框架剩余耐久比例，结算普通建设成本 |
| 施工失误 | 每个已交付批次保留随机半数且至少 1 单位，其余计入 destroyed；手中未交付材料不受影响 |
| 余料可落地 | 保留实际物资状态并放下；产生新身份、零进度、未交付材料的普通计划 |
| 上层梯段没有同层实物落点 | 余料沿局部重力寻找下方/相邻合法落点，再重新搬上施工；不会卡在尚未建成的梯段里 |
| 余料没有附近落点 | 保留有限的失败容器，停止施工和领取材料；清理空间后再落地和替换计划，不再次抽签或扣料 |
| 取消失败容器 | 不再重试；只退回余料，满地时仍等待合法落点 |
| 余料继续被火烧 | 木材、布料和零部件仍是燃料；额外烧毁单独记录，存读后不会恢复或重复损失 |
| 失败工地的支撑烧毁 | 用建筑自身的支撑规则处理余料损毁，删除失去支撑的计划，不留下悬空重试蓝图 |
| 货架施工失败 | 新蓝图继承收纳设置和原联动组，普通搬料和完工继续接管该成员身份 |

地板与桥虽然没有普通可燃施工框架，仍会施工失败。安装、卸下旧家具，拆除、采矿、生产账单和即时制作点不经过本条失败过程。当前没有教程模式、非玩家施工队、材质全目录和原版所有建筑 Comp。

## 概率与三维适配

每次实际劳动使用 `1 - S^(本次工作量 / 总工作量)`，保留原版最后一步完整工作量的微小超额风险。不同工作速度或工期不会被错误地当成每 tick 固定失误率。学习先于能力计算；技能超过 8 的基础加成先参与身体能力折算，再限制最终成功率到 0–1。

Web 用世界种子、任务身份、实际劳动次数和工人身份计算独立随机值。等待、渲染、倍速批量步进、保存和加载不推进抽样；失败后新蓝图具有新身份。没有复现原版的全局 Rand 序列，也不主张相同种子产生原版相同的失误时刻。

本项目交付物资按资源/作物种类合并，耐久使用已有加权合堆规则。失误针对**工地中实际合并后的批次**取余料；不是对曾经搬过来的每一堆另取至少一单位。原版是逐 `resourceContainer` stack，具体堆叠划分可能不同。

满地保留失败容器属于 Web 的明确适配：保证现有有限格子、任务容量和物资账一致。原版 `TryDrop` 失败的路径仅记录警告并跳出，静态证据不能证明其在极端拥堵下同样无损。Web 的支持关系、两格高墙和跨层地形也不是原版二维地图的机制。

## 存档与验证

存档升级为 v47。失败容器保存施工者、已经损失的数量、额外烧毁数量和幸存实物；读取严格核对成本、损耗、物资批次、劳动状态和字段类型。v1–46 不补抽过去的施工，不重置现有进度；拒绝旧版本伪装携带新版失败字段。

改动前从已提交的原 v46 模型生成并冻结一份实际施工 20 workTicks 的椅子工地存档。其地图、开局物资和公开命令未改写。这是**模型生成的旧档**，不是玩家或浏览器导出的实机存档。验证器从原 Git 树重建旧 bundle 并逐字节匹配，迁移后继续实际施工，在劳动中途保存加载，完工后再次保存加载，并逐 tick 检查木材守恒。

验证材料：

- [静态提取清单](evidence/construction-failure-manifest.json)与[机制证据](evidence/construction-failure-mechanisms.json)：16 个类型、47 个锚点、5 项有界检查、4 项打包 XML 投影。
- `tests/voxel-construction-failure.test.ts`：概率分段、能力影响、真实失误、补料完成、拥堵保存/取消、暂停续作、货架组、批次耐久、余料火灾和支撑损毁。
- [旧档来源](evidence/construction-failure-v46-provenance.json)和 `scripts/voxel-construction-failure-legacy-verify.mjs`：原样 v46 工地迁移和真实续建。
- [冻结验证记录](evidence/construction-failure-voxel-validation.json)：当前源码、测试、静态证据、旧档验证与构建文件哈希。

最终覆盖 **122 个测试文件、1,629 项测试，0 跳过**，其中新增施工失败专项 17 项。相关联动回归 24 个文件、325 项通过；上层梯段落料修复后，再跑 4 个施工相关文件、71 项测试及整份 17 项食物测试，均通过。类型检查与生产构建通过。长时食物准备实际推进 **97,025 tick（8.085 游戏日）**、收获 **90 份谷物**，准备阶段耗时 **256,810 ms**，逐 tick 检查账目；这些数字来自本轮最终日志。

原样 v46 工地从 tick 57、20 workTicks 迁移，继续实际施工，在累计 21/41/61 workTicks 三次保存加载，经过 **123 个续行 tick** 于 tick 180 完工。最终地面木材 75、消耗 15、损毁 0，总账仍为 90；此历史样本没有抽中失误，失误分支由专项测试另行证明。

完整回归中的旧守恒断言补入了已经存在的 destroyed 账项，未跳过实际劳动或物资检查。框架损伤继承的专门测试使用健康建造技能 8 的工人，以隔离「原框架完工」与「失误后替换成新框架」；新失败测试另行覆盖后一种行为。旧档版本断言更新为 v47。

长时食物回归还发现上层梯段失误后无同层落点导致建设等待。实现补上局部向下落料，保留原有跨层楼板建造、遮光停止生长、拆除后恢复生长的完整测试要求；修复后重新执行有关施工回归及整份食物测试，没有绕过梯段失误或把工人改成保证成功来规避卡点。
