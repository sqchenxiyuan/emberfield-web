# 102 家具施工品质与生活反馈

本轮把建造分工接到家具的实际使用效果：选择施工者 → 实体运料和施工 → 完工时确定品质 → 分配床位或使用餐椅 → 睡眠、舒适和房间评价改变。仍优先搭好玩法和机制，沿用现有木家具成本、工时与基础属性，后续再调整经济和节奏。

原版派生规则见[100](100-furniture-quality-mechanisms.md)，原版操作与观察边界见[101](101-native-furniture-quality-runtime.md)。静态规则、实机观察和Web实现分别记录，不以一次结果证明品质概率分布。

## 玩家如何使用

1. 在人物分工中安排建造者。木床、木餐桌和木餐椅都按建造技能完成，实际施工积累建造经验；搬运材料本身不产生一次额外品质判定。
2. 放置蓝图，居民实际取料、配送和施工。品质在成功完成时由完工者的建造技能决定；开工者、下单时选择的人物和搬运者不会提前锁定品质。
3. 点击家具查看品质、耐久、美观、估值，以及床的睡眠恢复或床椅的额定舒适度。可把更合适的床分配给需要它的人，现有医疗床、囚犯床和餐桌聚会开关继续有效。
4. 居民实际睡在床上或坐在餐椅上时才获得对应效果。人物面板显示正在使用的家具，并可定位查看。更好的餐桌不会替代较差餐椅的舒适效果。

## 各属性的作用

| 属性 | 当前效果 |
| --- | --- |
| 品质 | 木床、木餐桌和木餐椅各自保存；普通施工没有灵感，不能自然产出传奇 |
| 睡眠恢复 | 只作用于实际使用的床，包括未倒地居民的有效医疗休养和囚犯睡眠；地面休息仍使用原有较慢速度。倒地居民沿用已有床位舒适与医疗效果，本轮未补充其精力恢复 |
| 舒适 | 来自实际床椅，逐步影响人物舒适需求；额定值可以超过100%，人物需求本身最多100% |
| 美观 | 加入家具所在房间的美观统计，继而影响房间印象和既有生活记忆 |
| 价值 | 家具品质先作用于建材与工时估值，再按实际损伤修正市值；房间使用该市值，殖民地建筑财富则按原版忽略损伤，仍计品质 |
| 耐久 | 原版这几种家具的最大耐久没有品质修正；Web也保留既有耐久上限，不把高品质变成额外血量 |

马蹄铁柱、围栏与普通工作台没有被追加虚构的品质。围栏、栏门、圈地标记及桌椅此前漏接建造技能的工作分类一并修正，现在这些实际建造工作使用已有建造速度与经验机制。

## 中断、损伤与存档

完工前可以改变分工、征召施工者、取消蓝图或保存退出。成品只在材料和放置检查成功后生成一次品质；等待被占位置时不提前抽取，修理和读档也不会重新抽取。随机流以世界种子、工程和实际完工者区分，保持与渲染帧无关；它是Web对原版全局随机流的明确适配。

损伤降低家具当前耐久、市值和房间财富，修理恢复耐久，均不改变品质。叙事者使用的殖民地建筑财富忽略损伤，不能靠损坏家具直接降低这一部分威胁财富；拆除或烧毁导致实体消失后才移除其建筑价值。拆除仍按原有材料退还机制处理，不因高品质多返材料。当前没有搬移或重装家具，也没有施工框架血量；原版施工框架的损伤比例传给成品这一分支尚未实现。

v33为已有床、桌、椅添加品质字段。真实v32及更早存档的家具升级为普通品质，保留身份、归属、聚会开关、损伤、食物和在途任务；不会凭当前居民技能改写旧家具。新版缺失、非整数或越界品质会被拒绝，旧版夹带新品质字段也不会静默接受。迁移夹具来自已发布v32代码通过普通命令生成的营地，保留原始字节与来源记录。

## 本轮边界

- 基础材质只保留现有木家具，材质替换和多种家具目录继续后续扩展。
- 沿用已研究的普通制造品质分布，不包括灵感、专家角色、艺术描述或作者署名；没有虚构原版通用作者字段。
- 未增加建造失败、重装搬运、床位自动择优或全部房间设施。这些与家具品质是不同机制。
- 高品质影响现有房间和财富反馈，但本轮不宣称长期经济、威胁增长或睡眠平衡已校准。

## 验证入口

```sh
npm test
npm run build
npm run test:voxel:furniture
npm run test:voxel:furniture:browser
npm run research:furniture
```

规则与集成测试区分施工完成者、实际床椅使用、房间和财富反馈、品质与耐久的区别，以及中断与旧档延续。普通经营与浏览器验证使用未经编辑的新开局和实际玩家操作；控制品质的对比夹具只作为机制测试，不冒充普通经营随机结果。

本地覆盖86个测试文件、1108项测试：非食品回归先通过1084项，5项历史迁移预期未包含新增的普通品质字段；这两文件修正预期后13项全部通过，原始存档字节未改。八日真实收获与食品流程单独17项通过；建筑财富忽略耐久的修正后，家具与财富三个相关文件22项通过。保留各次原报告与逐文件覆盖汇总，不将首次失败报告写成全量一次通过。

八日收获仍实际推进到成熟和收获，没有缩短游戏内等待；其本地准备超时上限从180秒放宽到300秒，以容纳正常CPU争用，不作为游戏性能达标结论。

最终普通经营流程从新种子73129开始，实际推进至16174tick，通过50项检查；三张床自然产出较差、良好、普通品质。同一居民实际换床睡眠、到椅子用餐及休闲，记录真实使用效果。浏览器在Worker与主线程模式各通过14项检查，均无页面或控制台错误，执行资源与本地最终构建的哈希一致。宽屏和900px界面已检查，较长检查面板可以滚动。报告来源、边界、源文件与脚本哈希及页面截图见[本地验证记录](evidence/voxel-furniture-validation.json)。
