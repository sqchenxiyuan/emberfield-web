# 105 家具卸下、搬移与重装

v34把营地改造接到现有施工和物流：选择家具 → 卸下原物 → 单件打包家具落地 → 实际搬运或入库 → 在新位置重装 → 继续睡眠、用餐和休闲。品质、耐久和身份始终属于同一件家具。优先完成玩法闭环，工时和经济参数仍可后续调整。

原版派生规则与实机证据分别见[103](103-furniture-reinstall-mechanisms.md)、[104](104-native-furniture-reinstall-runtime.md)。原版为二维地图；跨层目标、楼板坠落和占地检查是本项目的三维适配。

## 玩家操作

1. 点击木床、木餐桌或木餐椅，选择「搬移」并点击新位置。可以切换楼层，按R旋转；Esc或右键退出放置预览。
2. 「卸下」只安排拆包工作，完成后得到一件可检查的打包家具。仓储允许接纳家具时，搬运者可把它搬入仓库；旧存档的仓储筛选保持原设置，需要玩家勾选家具。
3. 点击地面的打包家具，选择「安装」，放置新目标。工人必须取到指定的那一件，不能拿同类另一件替代。
4. 面板显示卸下、搬运、安装阶段和等待原因；取消搬装后已经卸下的家具仍保留实物。满地面时等待安全落点，不凭空退成木材。

直接搬移会串联卸下与安装两个任务。源家具在卸下成功前仍存在，完整实体落地后才离开原位置。工人必须沿实际通路搬到目标楼层；家具送达后安装立即完成，不增加虚构的长时间施工。目标有人、动物或无法挪开的物资时会等待。

## 保留与重置

| 状态 | 搬装结果 |
|---|---|
| 家具身份、品质、当前耐久 | 保留，包括小数耐久；重装不抽品质、不修复损伤 |
| 位置和朝向 | 使用玩家选择的新目标 |
| 餐桌聚会开关 | 保留 |
| 普通床原主人 | 作为候选保留；重装时仅在其仍是存活殖民者、没有其他所属床且目标不是牢房时恢复 |
| 医疗床、囚犯床用途 | 卸下后重置；不携带它们的主人候选。装入既有牢房时沿用房间囚犯床规则 |
| 正在睡眠、用餐或聚会的人 | 释放旧家具使用与座位预约，重新安排 |
| 建材 | 不消耗新木材，不产生拆除返还；「拆除」仍是原有的材料回收操作 |

卸下使用建造速度但不给建造经验；安装不产生新家具品质或建造经验。初版默认卸下40工作量、安装1次调度事务，集中在 `src/voxel/relocation.ts`，不是精确的原版节奏校准。

## 实体物流、中断与灾害

同一家具只在已安装实体、地面包裹、人物携带、安装任务已交付容器四处之一存在。地面包裹可以换容器ID，内部家具ID不变。保存读档保留品质、耐久、施工进度与实物位置，恢复时重建临时任务预约。

搬运者被征召、倒地或死亡时，携带的家具尝试安全落地，另一位工人可以接手；地面已满则继续保留并重试。此规则只扩展家具，已有尸体普通补给保留机制不变。被其他人抱起的患者不在半途丢家具。

地面或安装现场的包裹被火烧时逐步扣除内部家具耐久，归零才损毁并取消相关任务。安装现场楼板失去支撑时，包裹按现有规则落到原列或相邻列最近合法地面；没有合法容纳位置则记录真实损毁。搬运者随身物品沿用已有火灾范围，本轮没有新增携带包裹的直接燃烧。

原版实机样本同时存在包装100/100 HP和内部木床91/91 HP两个字段，两者均为完好状态；不能拿包装上限100当作内床上限。Web首版只保存内部家具耐久，没有独立包装耐久，基础HP沿用既有暂定值。上述包裹燃烧是Web的明确简化；原版样本证明内部床当前耐久值保留，未实测受损家具或两版受火伤害结算的一致性。Web受损家具另由50.25 HP的控制夹具检验。

打包家具不按普通木材受环境劣化；这来自原版MinifiedThing没有继承内部建筑劣化属性的静态规则。它仍会受火灾损坏。安装时计入建筑财富，打包时计入物品财富；建筑财富忽略耐久、物品财富计耐久，两者的分类切换会改变财富构成，不做重复计价。

## 存档和范围

v34为资源账本添加家具，迁移已有数据时补零，不新增家具或重置原床桌椅。真实v33营地、睡眠中和用餐中存档逐字节保留为迁移夹具，并记录来源哈希。新版检查跨容器身份唯一、指定实例交付、合法品质/耐久、卸下位置与原物匹配、安装占地及总量上限。床/桌各128件、椅256件的上限包含打包状态，不能通过卸下来绕过。

首版只支持已有木床、木餐桌和木餐椅。工作台、电力设备、多材质目录、家具贸易、搬运重量与包装体积、施工框架损伤和建造失败仍待扩展。现有打包家具一件占一个仓位，尚未实现货架或箱中多件容器。

## 本地验证

```sh
npm test
npm run build
npm run test:voxel:relocation
npm run test:voxel:relocation:browser
npm run research:relocation
```

机制测试使用明确控制的房间，检查身份守恒、搬运存读、满地面取消、目标占用、人物中断、火灾和楼板坠落。正常经营脚本另从新世界开始，通过普通命令建设和搬装，禁止把修改后的历史存档冒充新开局证据。浏览器检查覆盖Worker和主线程两条渲染路径、真实按钮和地图操作。

测试均在本地运行。Pages流水线只安装依赖、检查类型、构建和部署。最终验证结果另存于本轮证据记录，失败和重跑报告保留，不把诊断运行当作最终源码的验收。

最终本地逐文件覆盖为91个测试文件、1150项通过。首次全量1139/1149通过，暴露历史账本零键预期、家具测试夹具缺少独立实例，以及v4默认仓储迁移误加入家具筛选的问题；修正后完整重跑相关文件。安装目标坍塌时联动取消源任务另补回归，新增一项。高并发下两次默认5秒超时通过CLI放宽到15秒重跑，未修改玩法速度或缩短模拟时长。汇总选择每个文件最后一次完整结果，不声称首轮全量一次通过，原报告均保留。

最终普通经营从种子73129重新开局，推进至16083tick，通过60项检查，包括地下家具搬到地表、先入库再安装、携带存读和取消、实际新床睡眠和新桌椅用餐。最终浏览器Worker与主线程各14项检查通过，无页面或控制台错误，运行资源SHA与最终本地构建一致。人工检查宽屏与900px界面，并修复选址栏旋转/退出按钮溢出；所有诊断轮次独立保留。来源哈希、完整检查条目与选定截图见[本地验证记录](evidence/voxel-relocation-validation.json)。
