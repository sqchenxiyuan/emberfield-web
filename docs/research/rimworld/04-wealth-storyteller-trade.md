# 财富、叙事压力、袭击组队与贸易

核对：2026-11-02，RimWorld **1.7.4980 rev60**。本章是静态派生分析，未运行原游戏。证据组 **RW17-ECONOMY**：[类型与哈希](evidence/economy-manifest.json)、[结论账本](evidence/economy-claims.json)、[XML声明快照](evidence/economy-xml.json)。所有 `类型:行号` 对应本地生成的 `.local-research/economy/<类型>.cs`，不是原始源码行号。

## 1. 财富至少有三个不同口径

**EC01–EC03**：记录器的总财富、叙事者输入的财富、出售能换到的银币，不能共用一个变量。

| 口径 | 计算/边界 |
|---|---|
| `WealthWatcher.WealthTotal` | 物品 I + 建筑 B + 玩家派系人物/动物等 P |
| 普通基地 `Map.PlayerWealthForStoryteller` | **I + 0.5 B + P**；只有被视为玩家基地、且未启用固定财富模式时使用 |
| 非基地地图 | 自由殖民者装备/衣物/背包的财富，加玩家动物市值；并非把整张地图资产计入 |
| 固定财富模式 | 基地走地图年龄 × 时间倍率的财富曲线，脱离实际库存 |
| 交易报价 | 市值另乘买卖价差、难度、商品、谈判与商人修正，见第6节 |

`WealthWatcher.ForceRecount`（115–171）：

- 人工建筑只有玩家派系的才计入，使用 **MarketValueIgnoreHp**，所以打残但未摧毁的建筑不会按其当前耐久比例降低这部分财富；地板计入 B。
- 玩家派系 Pawn 排除任务临时住客；奴隶的市值贡献乘 0.75。人口战斗点在后续单独添加，不能因为已经算过人物市值就删掉它。
- 附属 pocket map 的财富递归加回源地图。对应分支没有在实机世界中测过。
- 物品递归扫描 `HaulableEver`，要求物品或父容器已生成、所在位置不在迷雾中；容器过滤排除经过的飞船、MapComponent、非玩家 Pawn、任务住客。**物品最终累加处没有逐件检查“玩家所有”**，不要把它简化成仓库里已认领物品的总价。
- 顶层地形只在非迷雾格计价；`foundationGrid` 在该函数中独立累加，没有相同的迷雾判断。此为本版本代码分支，不推断每种世界生成是否会出现可见差异。

读取财富时，在 Playing 状态且距上次统计 **严格大于5,000 tick** 才自动重算；另有强制重算入口。因此它是按需刷新缓存，不能写成每5,000 tick必定触发一个后台任务。

来源：`RimWorld.WealthWatcher:42–49,107–171,203–261`；`Verse.Map:366–379,412–442`。

## 2. 财富与人口如何变成基础威胁点

**EC04–EC06**：`StorytellerUtility.DefaultThreatPointsNow`，131–189。

```text
base = wealthCurve(W) + Σ pawnContribution(pawn, W)
A = 1 + adaptationEffectFactor × (adaptationCurve(adaptDays) − 1)
P = clamp(base × targetRandom × A × threatScale × daysPassedFactor,
          GlobalPointsMin(), 10000)
```

普通 `Map` 的 `targetRandom` 明确是 **1**。不要把 Randy 的事件额外随机强度误加为所有地图都使用的随机项。口袋地图在此入口被转向源地图。

| W控制点 | 财富点 | 每名自由殖民者基础点 |
|---:|---:|---:|
| 0 | 0 | 15 |
| 10,000 | 位于0–14,000的零值段 | 15 |
| 14,000 | 0 | 插值 |
| 400,000 | 2,400 | 140 |
| 700,000 | 3,600 | 插值 |
| 1,000,000 | 4,200 | 200 |

`SimpleCurve.Evaluate` 在相邻点间线性插值，超端点用端点值（`Verse.SimpleCurve:139–169`），不是无限外推。所以表中两条曲线不是统一斜率，财富超过一百万时这两项也不继续线性增加。

每名人物还可能经过：

| 修正 | 规则 |
|---|---|
| 任务临时住客 | 跳过 |
| 健康 | 乘 `0.35 + 0.65 × SummaryHealthPercent`；健康50%时保留67.5%的点，并非只剩一半 |
| 低温休眠舱 | 先乘0.3 |
| 奴隶 | 在已产生正贡献的路径中再乘0.75 |
| Biotech人形年龄 | 曲线 `(3,0),(13,0.5),(18,1)`，其余由插值/端点规则决定 |
| 玩家、未倒地、可训练释放的动物 | `combatPower × 0.08`，商队另乘0.7 |
| 未倒地殖民地机械体 | `combatPower × wealthDependentFactor`，财富0/10k/400k/1m对应0.2/0.2/0.3/0.4 |

这些是互斥主体分类加后续修正，不能给同一动物同时加“殖民者点+动物点”。子人类另有曲线分支，未展开其全部内容定义。

下限不是永远35。`GlobalPointsMin` 用 `TicksGame / 2500` 作确定性随机种子，在35与难度上界之间抽取。上界曲线为 `(12日,35),(35日,minThreatPointsRangeCeiling)`；前12日范围退化为35，之后逐渐张开。来源：`StorytellerUtility:98–101`；`Difficulty:127,456–462`。

### 算例：三人基地

声明假设：I=20,000、B=20,000、Pawn市值P=6,000；3名健康成年自由殖民者，没有额外动物/机械体；普通基地；适应值0；难度威胁倍率1、适应影响0.9；基础父定义的第10日曲线；下限没有抬高结果。

```text
W = 20000 + 0.5×20000 + 6000 = 36000
财富点 = (36000−14000)/(400000−14000) × 2400 = 136.787565
每人点 = 15 + (36000−10000)/(400000−10000) ×125 = 23.333333
base = 136.787565 + 3×23.333333 = 206.787565
A = 1 + 0.9×(0.8−1) = 0.82
P = 206.787565 × 0.82 × 0.7 = 118.696062
```

这只是公式算例；**不是一次已经发生的118.7点袭击**，后续策略、到达方式和最小组队要求还会修改预算。

## 3. 适应系统是带伤亡反馈的隐状态

**EC07–EC08**：`StoryWatcher_Adaptation`，24–81。

- 每30,000 tick（半游戏日）检查增长。增量为 `0.5 × growthCurve(adaptDays)`，若当前适应值**大于0**，再乘难度正向增长倍率。
- 非负适应值在开局宽限期内不增长；负值仍允许恢复。基础 XML 声明宽限30日，最小−60、最大100。
- 人形殖民者且非囚犯才进入该事件入口；倒地必须附有对该角色判定为外部暴力的伤害，不能把饿晕、睡眠写成同样的压力降低。
- 同 tick 的暴力倒地先排队，后续失去该人物时可从队列移除，避免同一次死亡同时重复计算倒地与失去惩罚。
- 伤亡减少的是 `adaptDays`，再通过曲线映射到倍率，不是直接从袭击点数里减一个定额。

基础父定义的声明值（`Storytellers.xml /StorytellerDef[@Name='BaseStoryteller']`）：

| 曲线/字段 | 控制点 |
|---|---|
| 适应值→威胁因子 | `(-30,.4),(0,.8),(30,1),(60,1.2),(120,1.6),(180,2)` |
| 暴力倒地扣值，按当前人口 | `(1,8),(2,6),(3,6),(11,5),(20,3.5)` |
| 失去人物扣值，按失去后的计算人口 | `(0,30),(11,30),(20,20)` |
| 建立殖民地后的时间倍率 | `(10,.7),(40,1)` |
| 正负适应增长 | `(-30.01,6),(-30,3),(-.01,3),(0,1),(59.99,1),(60,.5),(119.99,.5),(120,.25)` |

Cassandra、Phoebe、Randy 的 XML 均声明继承该父定义；本轮保留父声明与 `ParentName`，未模拟整个加载期的补丁/继承。因此表格不承诺所有启用 Mod 的最终有效值。

**容易误读的边界：** 父定义适应上限100，故其正常增长可到达的原始因子为 `1.2+(100−60)/(120−60)×0.4=1.466667`。曲线里虽有180→2，也不能据此宣称普通增长最终一定翻倍。调试设置/其他定义另论。

算例：3人、适应值30时，一名角色被暴力击倒，按该人口扣6，变24。原始因子从1变为 `0.8+24/30×0.2=.96`；适应影响0.9时，最终倍率从1降为 `.964`，不是降低6%或直接减6威胁点。

难度 XML 中 `threatScale` 声明：Peaceful=.10、Easy=.30、Medium=.60、Rough=1、Hard=1.55、Extreme=2.2。Peaceful还单独禁用大威胁，不能因倍率非零就推断和平难度会触发常规大袭击。Rough/Hard/Extreme 的适应影响分别 .9/.7/.4。

## 4. 事件节奏与威胁强度分开计算

**EC09**：`IncidentCycleUtility:12–115`，`StorytellerComp_OnOffCycle:10–88`。

On/Off调度先把天数按 `round(days×60)` 转成 **1,000 tick区间**；根据世界持久随机值、目标种子、组件序号、周期号重建该周期命中列表。生成时处理数量范围、最小间隔、上周期保留命中列表的末项，再按接受比例裁剪。接受比例小于1时会打乱并裁剪列表而不重新排序，故“末项”不保证是时间最大的事件；不能据此声称所有条件下跨周期最小间隔都严格保证。

因此“4.6日活动/6日休息”是活动窗口参数，不是严格每10.6日固定在相同钟点来一波。窗口命中后还要经过事件类别、具体事件是否可触发、生成是否成功。基础 OnOff 组件支持前期强制选 RaidEnemy，但仍调用 `CanFireNow`。本轮补齐调度算法入口，未复刻游戏随机数算法，也未验证所有叙事者组件间的竞争与全局队列顺序。

算例：1.9日最小间隔对应114个区间，即114,000 tick；4.6日活动窗口对应276个区间。它们是游戏时间，不是网页计时器毫秒。

## 5. 威胁点如何变成敌人

**EC10–EC11**：调用链为 `TryGenerateRaidInfo → 选派系/策略/到达方式 → AdjustedRaidPoints → 策略专属SpawnThreats或PawnGroupMaker → Arrive`。

预算依次乘：到达方式曲线（用当时点数求值）、策略曲线（用已修改点数求值）、年龄限制倍率、世界层倍率。最后至少为 `策略MinimumPoints × 1.05`。所以前一阶段的10,000上限**不能直接当成所有最终袭击组队预算的统一上限**。

正常组队的单位基础成本来自 `PawnKindDef.combatPower`，基因类型可再修正。候选会被剩余点数、单位最高成本、策略、年龄、同种最大数量、首领限制等过滤；抽到一个单位后扣预算继续，直到没有可选单位。特殊策略可以自己生成威胁，不能宣称一切袭击都走同一个背包算法。

选择权重还乘一条“单位成本/迄今最高可选成本”的曲线：比值 .2/.3/.5对应 .01/.3/1。成本较低的单位并非默认更容易出现。最近袭击派系的候选权重另乘 .4，避免同派系过度连续出现。

边界示例：传入预算100，到达倍率.8、策略倍率1、最低策略点90，则最后为 `max(80,90×1.05)=94.5`。若所有可用单位成本为40，且其他限制都允许，正常扣点最多取2个，剩14.5。这个例子使用人为参数解释规则，不代表某个原版派系固定产出两人。

来源：`IncidentWorker_Raid:70–127,191–211`；`PawnGroupMakerUtility:97–291,355–381`；`PawnGenOption:12`。

## 6. 贸易价差与数值

**EC12–EC14**：银币路径，令 V为该物品市值，L为难度交易损失，N为谈判改善，S为据点报价改善：

```text
卖出 = V × .6 × 商人卖价档倍率 × SellPriceFactor × 人物卖价倍率
         × (1−L) × (1+N+S+药物奖金+畜产品奖金)
买入 = V × 1.4 × 商人买价档倍率 × 招募身份倍率
         × (1+L) × (1−N−S)
```

先各自裁到卖出至少.01、买入至少.5；单价**大于99.5**时再取整。`Tradeable.InitPriceDataIfNeeded` 最后把卖出单价封顶到买入单价，避免同一会话中的倒买倒卖价差反转。货币本身走市值等价路径；恩典交易有专门分支，不能套上面银币公式。

| 商人价格档 | 倍率 |
|---|---:|
| VeryCheap | .4 |
| Cheap | .7 |
| Normal | 1 |
| Expensive | 2 |
| Exorbitant | 5 |

Hard/Extreme 的 XML 交易损失分别 .10/.20。`SellPriceFactor`、物品市值的品质/耐久等来源仍需要逐类追踪，表格不是对所有商品都按原价60%卖、140%买的保证。

三个计算例（普通银币商品，未写出的乘数均为1、加项均为0）：

| V、参数 | 卖出 | 买入 | 意义 |
|---|---:|---:|---|
| V=100，L=0，N=0 | 60 | 140 | 基础买卖价差 |
| V=100，L=.1，N=.1 | 59.4 | 139（138.6取整） | 同时受难度与谈判，不能合成一个通用折扣 |
| V=.01，L=0，N=0 | .01 | .5 | 最低价格使低价商品表现非线性 |

来源：`TradeUtility:256–283`；`Tradeable:250–294`；`PriceTypeUtlity:8–19`。

## 7. 对 Emberfield 的设计含义

以下为**实现建议**，不是原版源码或本轮已完成的功能：

1. 拆开资产市值、出售价格、叙事财富、战斗实力与即时战斗点；记录计算明细供调试与平衡分析。建筑按半价计入使建基地与囤货产生不同风险，不能只按库存数量增长敌人。
2. 把事件“何时来”“是什么”“有多强”“如何组队/到达”分成四个阶段。强度曲线可以逐步替换，不必先复制全部袭击种类。
3. 用持久化的适应状态反馈真实损失；必须定义同 tick 倒地和死亡的去重、冷却与恢复速度，避免反复触发降难度。
4. 每个组队器提供 `canGenerate/minimumBudget`。不足最低成本时应明确跳过、延期或抬预算，不能发送空袭击通知。
5. 财富缓存可按相关资产变化标脏；进行下一次事件取值前刷新。Web版可用自己的更新粒度，无需把原版5,000 tick机械照搬为现实时间。

截至本轮，Emberfield 的普通袭击在 `src/sim/world.ts` 以轮次增长预算、伤后延期、4–6日间隔实现；没有完整财富统计、原版适应曲线、派系组队和贸易。原版公式使用60,000 tick/日；Web模拟自己的20TPS与游戏日刻度需要显式换算，不能直接移植tick常数。
