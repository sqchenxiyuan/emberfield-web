# v51：鸡蛋、孵化与食物生产

本轮接通受精蛋取得、幼鸡孵化、成长圈养、接触配种、母鸡自行产蛋、食物与新一代鸡的循环。继续优先搭建玩法与机制，产量、成长时间和长期经济后调。原版安装文件与派生代码依据见[145 原版机制](145-animal-eggs-mechanisms.md)。

## 取得与养殖

目前大宗商队在原有商品之后固定带来 4 枚受精鸡蛋，可实际交谈、报价和支付银币取得；购买的部分改为殖民地归属，剩余商队蛋不改，成交后重放同一请求不能重复购买。**这是 Web 的临时取得入口**：所查 Core 大宗食物生成器排除了受精蛋，原版农场动物更常通过活畜交易取得。当前尚没有活畜交易，也没有把鸡伪装成原版温带野生动物。固定追加不消耗原商品的随机数。

受精蛋在地面、货架、殖民者携带、工作台原料及商队库存中按所在格温度孵化；不会因为换容器停止计时。默认 3.5 Web 日孵化，每枚蛋产生有独立 ID、性别、成长、饥饿和归属的幼鸡。性别按确定性随机生成，不保证买两枚就有一公一母。幼鸡初始饱食使用本模型“饥饿”和“急需进食”阈值中点，需及时提供草地或粮食。

鸡接入已有圈地接纳、牵引、围栏、自动宰杀、人工宰杀和尸体加工。成年母鸡即使没有公鸡也会形成未受精蛋；饥饿减慢或暂停形成，但已有的满蛋仍可产下。母鸡产蛋没有派系条件。殖民地公鸡实际走到兼容母鸡旁完成配种，直接赋予下一枚蛋的受精额度，不走哺乳动物的怀孕和受孕概率。额度为 1，下一枚产下后用尽；没有“母鸡怀孕”的状态。

鸡使用现有 Web 动物成长曲线（饱食约 4 天成年），而不是原版鸡 0.2 年成年；原版年龄数据和简化差异在145章中分别记录。鸡生命、肉量、移动、交配间隔也仍为原型参数。

## 自己走到产蛋位置

满蛋后母鸡优先寻找同一房间内、30 格范围内、本轮实际蛋类型的可达地面堆，找不到时使用附近可达位置。它会实际行走并完成产蛋等待，不需要殖民者执行挤奶式任务。路径遵守三维地形、围栏和已有动物区域规则。

威胁、牵引和饲养员互动可中断等待，生物蛋进度与受精额度保留；新任务重新等待，原任务存读则保留具体位置、路径和工作进度。产物整批放置预检成功后才重置生物进度和扣受精额度。满地面时显示等待并重试，不重复生产。这项保护是 Web 适配，原版最终放置失败并不回滚已经执行的 ProduceEgg。

**蛋箱及自动清箱尚未实现。** 原版蛋箱容量、20 枚自动搬空阈值和搬运工作已记录在145章；当前没有用隐形蛋箱或抽象库存冒充这些机制。

## 孵化、温度与实物身份

活性受精蛋不腐败。0～50°C 不增加温度损伤，超界按温差积累，回到安全温度不恢复损伤；未完全损坏前仍继续孵化。完全损坏时转成新鲜、默认满耐久的未受精蛋，可继续吃或做饭，之后才使用普通鸡蛋的 15 天腐败时钟。因此，冷冻食用蛋与保存孵化蛋是不同选择。

受精蛋每堆保存一套孵化进度、温损、父母历史身份和派系。拆堆精确复制；合堆按实际转移数量加权进度与温损，接收堆保留自身父母和派系，符合所查原版堆叠行为。不是每枚蛋偷偷附带一个独立计时器。放置预演不会改变原堆进度。

完成孵化后逐枚寻找附近合法空位，受已有 128 动物上限约束。无法放置的部分保留完成进度，等待空位或容量；这也是明确的 Web 拥堵保护。生成雏鸡只取容器坐标，不能拷贝持有者的技能、装备、物品或工作台原料。

温损或孵化导致物品变化时释放原取物预约。携带任务重新安排；若厨房已配送的受精蛋变化，则取消本次烹饪并退回实际剩余原料。退款空间不足时保留取消任务内的实物，保存后仍可继续退料。温损转换记作受精蛋消耗与未受精蛋产出，孵化记作受精蛋消耗，不凭空抹掉数量。

商队库存参与温度和孵化，但不记入殖民地资源账本；当前动物只区分殖民地与野生，商人持有或买走的蛋按非殖民地归属孵化，不代表已实现完整动物阵营外交。

## 食材与生活反馈

每枚鸡蛋提供 0.25 营养，简餐需要 0.5 营养。两枚蛋可做一份简餐，同类/不同类食材按实际营养选择，允许最后一个不可分物品造成有限超额；不把一个蛋当一粒谷物，也不消费小数枚蛋。

新料理账单默认允许未受精蛋，受精蛋必须明确勾选。普通自主进食优先使用其他食物，地面受精蛋只在饱食为 0 时才进入候选；已经携带的食物保留所查原版库存回退差异，可在未到 0 时食用。两类生蛋都会产生生食记忆和每次进食 2% 中毒风险。护理按病人的营养缺口取真实枚数；目前护理地面受精蛋沿用相同门槛，这个护理入口尚未独立核对原版。

界面新增鸡的肖像、产蛋与受精状态、真实工作进度，蛋的孵化与温损信息，以及食用蛋/孵化蛋独立仓储预设。程序几何区分双腿有翅膀的鸡、成长阶段、蛋壳和受精斑点；产蛋动作只随实际工作进度改变，暂停或堵塞时不继续空转。

## 存档与验证边界

存档升级 v51。旧动物补零进度，旧圈地不自动收鸡，旧自动宰杀鸡配额不限，资源账本补零。旧存档不会生成鸡或蛋，也不会扩大旧仓库、料理或屠宰筛选；旧隐式工作台账单物化为原 legacy 身份并保持原选择，已领取工作保留原材料。旧版本夹带新机制字段会在历史默认补全前拒绝。

历史连续性使用精确冻结的已发布 v50 模型，从已有真实经营检查点经公开指令和 158 tick 生成正在做饭及裁缝加工的 v50 存档；新版与冻结模型逐 tick 对照完整状态，共 750 tick、4 次存读，完成 1 份简餐和 1 顶布料保暖帽。对照只消除明确断言为零的新字段、版本标签及隐式/显式账单表示差异，保留人物移动、任务归属、物料与加工进度。早期 v1～v4 默认仓储也保留既有资源集合，不把新食材插入历史筛选推断。

新增测试采用明确的控制地形、成体动物、初始材料和临界孵化进度，覆盖真实行走、配种、产蛋、搬运、烹饪、食用、交易和中途存读，以及满空间、受损转换、原料孵化和身份校验。**临界进度夹具不是从新营地自然经营完整繁殖周期的验收。** 原版机制来自静态派生和 XML，不是本轮原版运行证明；界面测试为 SSR 与无 GPU 的几何/拾取/动画状态检查，不是视觉验收。

完整回归、构建及历史对照的最终结果与文件哈希见[本轮验证摘要](evidence/animal-eggs-voxel-validation.json)。没有启动或控制原版、浏览器、预览或其他 GUI。发布流水线仍仅安装、构建、部署，测试在本地执行。

本地全量及受影响完整文件复跑合计覆盖 **133 个文件、1,764 个测试，最终全部通过，无跳过**；首次失败与后续复跑均保留于摘要，不将它们描述为一次全绿运行。TypeScript 检查与生产构建通过，记录 28 个构建文件。原版静态复核通过 43 个派生类型、115 个锚点、9 项限定检查、25 个 XML 投影及 6 个 Core 生态文件的限定缺席检查。

后续继续补蛋箱/清箱、活畜交易、动物训练与医疗等缺口；全局产量、价格、人口与饲料经济在主要机制完成后再调整。
