# 10 首个多层体素切片的资源参数映射

日期：2026-11-02。目标是给 [08 多层体素方案](08-voxel-feasibility.md) 的 **64×64×16、两格净空、地表脚部 z=8** 切片提供可直接实施的最小资源集。本章复用已经提取的本地证据，没有重新全量反编译，也没有执行原版或修改游戏实现。

后续实现已推进到[26章岩块切石链](26-voxel-stonecutting-implementation.md)：当前天然石概率产原始岩块，再加工石砖。本文保留首个施工切片的提案来源，不作为当前资源链的完整说明。

**建议先只启用木材与一种地下金属。** 默认切片保留“白杨参考产量27木材/棵、钢矿参考产量40钢/块”这两个数值；二维原版的矿脉格数、分布、工作时序与空间规则不直接照搬成三维。下文凡标记“自定”的数字均是 Emberfield 提案，尚未得到可玩性测试支持。

## 2. 先固定坐标和产量单位

切片采用 **x/y 为水平面、z 为高度**；这与原版派生代码常见的平面 x/z 用法不同。坐标转换应显式发生，不能把原 `IntVec3.z` 字段直接当本切片高度。

沿用08的约定：

| 名称 | 脚部站立空气格 | 身体需要的空气格 | 支撑实心块 |
|---|---:|---|---:|
| 地表 | z=8 | z=8、9 | z=7 |
| 地下工作层 | z=5 | z=5、6 | z=4 |
| 上层楼面 | z=11 | z=11、12 | z=10 |

因此“地表 z=8”不是“实心泥土一直填到 z=8”。范围为 x/y=0…63、z=0…15，共65,536个体素。台阶的中间站位可使用其他脚部高度；资源坐标必须携带完整 x/y/z。

本章建议的计量约定属于自定规则：

- 一个可采金属体素是一个资源节点；每个节点完整采完产生40单位钢。这个单位映射借用了原版单格产量，**没有证据表明一个体素等于原版一个立方米矿体**。
- 一棵树是一个有稳定ID的资源实体；整棵完成一次采伐产生27单位木材。树干/树冠可由多个可见方块组成，但这些方块不各自携带27单位产量。
- “矿块HP”“工作量”“产出物品数”“空间体积”使用不同字段。不要因为参考矿HP=1500，就把它当作1500单位矿物储量。

## 4. 矿脉总量：用水平面积作参照，不乘层数

原版数量函数先做 `divisor=Round(10000/rate)`，再做 `count=Round(mapSizeX²/divisor)`，后面还可有非初始图资源系数和placementFactor；这里不是三维体积函数。[GN16]

在64×64平面、系数均为1时，计算结果为：

| 山地类型 | 原基率/万格 | divisor | 64²上的尝试数 |
|---|---:|---:|---:|
| Flat | 4 | 2500 | 2 |
| SmallHills | 8 | 1250 | 3 |
| LargeHills | 11 | 909 | 5 |
| Mountainous | 15 | 667 | 6 |
| Impassable | 16 | 625 | 7 |

原版中心点需有天然岩体；找不到中心会结束剩余生成。这张表因此是“尝试数”。原版未提供“每个深度层重新生成这么多矿脉”的证据。把65,536体素代入原二维面积密度，或逐层各生成一遍，会把资源基准放大约16倍，且空气/地板也被错误计入。

原版30–40格的钢矿脉可以作为未来大地图参考；首切片若固定两簇都用这个范围，就有60–80块、基础产量2400–3200钢，可能掩盖资源与运输成本。是否过多最终取决于施工消耗与劳动时间；不能仅凭一个总量宣布原版平衡失效。

## 5. 推荐首切片参数：所有新增规则单独标记

这是一个建议配置，尚未写入运行代码，也不是已通过的平衡方案。

| 参数 | 建议值 | 性质/理由 |
|---|---|---|
| 资源种类 | wood、steel | 自定最小集合；泥土/普通岩石暂不产可搬物 |
| 启用矿物 | 仅压实金属，权重1 | 保留一个原版参考权重；裁剪后的选择集为自定 |
| 单金属节点产出 | 40钢，掉落概率1 | 产量来自MineableSteel；1来自BuildingProperties类默认，本切片明确固定 |
| 矿脉数量 | 整张图2簇 | 自定固定预算；与原二维Flat在64²上的结果一致，不表示原3D规则 |
| 每簇大小 | 6–10个体素；固定回归seed可用8+8 | 自定缩小范围；不冒充原30–40格 |
| 矿脉高度 | z=5、6的天然岩石 | 自定首轮带宽；覆盖地下两格工作面，暂不做地质埋深曲线 |
| 矿脉连通 | 六面邻接；每簇至少跨两个z层 | 自定三维规则；避免每层独立散点伪装成立体矿脉 |
| 中心水平间距 | 至少8格 | 自定分区；原版基础间距5只作参考，不直接声称三维距离等价 |
| 可触及保障 | 至少一簇邻接预定地下工作面 | 自定保障；工作面与通路仍需玩家正常挖开 |
| 初始树木 | 6棵成熟、满血的白杨参考树 | 自定场景布置；至少3棵从出生区有可达采伐站位 |
| 每棵树产出 | 27木材，完整采伐结算一次 | 来自白杨产量；成熟满血且采收属性/难度为1时成立 |
| 首轮产量修正 | 难度1、MiningYield1、PlantHarvestYield1 | 自定固定条件，暂不引入技能差异与损耗随机性 |
| 金属采掘 | 4秒连续劳动/节点 | 自定交互时长，不使用原版HP/击打间隔换名伪装 |
| 普通岩石/土块挖掘 | 2秒/1.5秒，移除但无物品产出 | 自定简化；明确不同于原石块25%掉Chunk |
| 采树 | 6秒连续劳动/整棵 | 自定交互时长；不是原800work或原tick的直接等价 |
| 生长与再生 | 首切片关闭；保留growth=1 | 自定范围；15.05 growDays作为后续参考，不在本切片假装已模拟 |

两个6–10块矿脉对应12–20节点，即480–800钢；回归布局8+8对应640钢。6棵树对应162木材。**这只是潜在可采总量，不是开局库存，也不意味着全部已经可达。**

施工配方不在本组证据范围。实现者应把“楼梯＋上层楼板＋墙＋储物点/工作站”的所需材料汇总，与162木材/至少一簇可触及的240–400钢作预算比较；若不足，应改明确的配方或生成参数，不能在测试中直接补库存后声称闭环通过。

工作持续时间建议用秒定义，运行时按模拟频率换算，不与渲染帧率绑定。20 TPS时，4/2/1.5/6秒分别为80/40/30/120模拟tick。迁移TPS时保持秒不变；这些数值全部是首切片新设计。

## 6. 三维生成的最小实现顺序

以下流程是新算法建议，不是原版 `IrregularLump` 的三维反编译版本。

1. 生成64×64×16底图：例如z=0为不可挖底界，z=1…6为可挖岩石，z=7为表土，z≥8为空气；只对出生区域采用此平整基线。以后加高差时仍以站立面规则计算，不硬编码所有树在8层。
2. 记录出生区、地表采树站位、拟开挖下行路线和地下工作面的**生成保护体积**。保护体积用于避免资源堵住必要施工空间，不意味着预先挖通、预先建完楼梯或给角色传送。
3. 为矿脉使用独立、可版本化的随机流。选择天然岩石中心，再从六面邻接边界集合逐步抽取未占用岩格，直到满足簇大小；每格都验证边界、基底材质和保护体积。这里“所有格必须是岩石”的要求比当前已确认的原版中心条件更明确，是自定规则。
4. 先安排一簇邻接拟开挖工作面，保证至少一个节点在完成合法下行通路后可从地下脚部z=5的站位触及；另一簇自由采样。两簇不重叠，且生成不得跨chunk边界意外截断同一个逻辑簇。
5. 对“有限挖掘后可触及”做规划可达性检查，不能只用当前空气格BFS声称地下资源无路，也不能在检查失败时把整段通路变成空气。若生成失败，有限次重试或用明确布局模板回退，记录原因与修改坐标。
6. 放置6个树实体及其可视占用，每棵绑定唯一root/owner ID。检查地面支撑、与出生/楼梯区域不冲突，以及至少3棵存在正常采伐站位。
7. 输出摘要：各矿簇的节点数/高度范围、总资源潜量、已可达树数、计划通路的挖掘块数、是否发生保障回退、seed、generatorVersion、rulesetHash。没有行为运行记录前只称“生成检查通过”。

最小可保存配置示意：

```ts
const sliceResources = {
  rulesetId: "voxel-slice-resources-v1", // 新设计版本，不是RimWorld版本
  size: { x: 64, y: 64, z: 16 },
  surfaceFeetZ: 8,
  pawnClearance: 2,
  materials: { compactedMetal: { product: "steel", baseYield: 40, workSeconds: 4 } },
  ore: { count: 2, size: [6, 10], zRange: [5, 6], weight: 1, minHorizontalSpacing: 8 },
  tree: { count: 6, product: "wood", baseYield: 27, growth: 1, workSeconds: 6 },
  difficultyYieldFactor: 1,
  miningYieldStat: 1,
  harvestYieldStat: 1,
};
```

“固定seed”只约束本实现的生成版本。换RNG、改变遍历顺序、加入新资源类型都会改变输出；不保证与RimWorld相同seed逐格相同。

## 7. 保留产量公式时，哪些条件不能漏掉

### 7.1 金属节点

原版的 MiningYield 是按有效挖掘伤害占最大HP的比例累计，而不是掉矿成功率：[GN20]

```text
q = sum(effectiveMiningDamage_i / maxHP * minerYield_i)
effectiveBase = round(baseYield * mineDifficultyFactor)
output = max(1, RoundRandom(max(1,effectiveBase) * q))  // wasteable路径
```

完整挖掉一个未受其他伤害的节点、所有矿工产量属性1、难度1时q=1，钢的产量即40。首切片可以固定这个条件，但不要一边不保存受损/贡献状态，一边开放不同矿工产量与非采掘伤害后宣称已复现公式。

原版矿HP1500、天然岩石每击80、击打间隔 `Round(100/MiningSpeed)` 是另一套时间模型。[GN19] 本章4秒工作进度制不执行这套伤害循环；建议暂时不把1500HP显示为“采掘进度”，避免两套量纲混合。以后接战斗破坏时再决定资源HP与采掘劳动的关系。

### 7.2 树木节点

白杨直接声明 growDays=15.05、harvestWork=800、harvestYield=27；橡树则为30、1400、46。TreeBase提供WoodLog、harvestMinGrowth=0.4、harvestFailable=false、肥力敏感度0.5和基础HP200。[GN32]

即使树不可采收失败，也不是任意成长/血量都产27。其生长门槛是**严格大于0.4**，收成受成长和HP修正：[GN28–30]

```text
gFactor = .5 + .5 * clamp01((growth-.4)/.6)
hpFactor = .5 + .5 * hp/maxHP
yield = RoundRandom(27 * gFactor * hpFactor * cropDifficultyFactor)
```

本切片把growth、HP比例、难度与属性都固定为1，才可以确定产27。若以后加入“砍幼树”或火烧树，需恢复上述修正，并处理树桩/采后状态。不能把参考中的harvestWork800直接写成800毫秒；原工作速度还包含 `PlantWorkSpeed * Lerp(3.3,1,Growth)`，与本章6秒工作制不同。

树的多个占用体素必须共享同一个采伐事务：完成时移除该owner的可采占用，并只结算一次木材。保存回读与重复完成通知也不能再次结算同一棵树。

## 8. 掉落、工作面和跨层守恒

本节是为了让最小切片可验证而制定的新空间规则。

- 普通采矿只允许从有支撑、两格净空的站位接近工作面；目标需在同一水平四邻方向的脚部或头部高度。特殊楼梯挖掘另用分步规则，不能让普通任务隔着整墙远程挖矿。
- 禁止在角色占用期间移除其支撑块，或建造占用其身体空间的块；下行施工由专门的安全步骤处理。
- 一个两格高走廊的上半格先挖空后，下半格尚未清除时不能被当成可走节点。导航缓存必须感知两格净空与支撑变化。
- 首版可把产物放到工作者脚部所在的合法物品格或同层邻格，随后由正常搬运任务运输。这是三维落物简化；原矿产物是尝试在矿物位置附近放置，不能称为完全同一规则。[GN20]
- 若所有允许的落物/携带容量都不足，保留待结算产出并暂停完成事务，或先预定产出位置。不能删除矿块后默默丢产物，也不能已生成物品后重试又生成一次。
- 地下采矿只能产生地下掉落/携带物，不能直接加到地表仓库。树木只能在地表产出，才能验证跨层物流有真实成本。

按每种材料分别检查：

```text
起始数量 + 已结算生产量
  = 地面散落 + 角色携带 + 仓库存量 + 未完工工地内材料
    + 已消耗材料 + 已记录销毁量
```

各容器互斥计数；“预定”只是锁，不凭空多一份库存。初始木材/钢建议均为0。未采矿体与未砍树的潜量另计，不加入可用库存；采矿/采树完成事务才将潜量转为物品。

完成事务需要稳定ID或等价的一次性标记；存档至少保存剩余资源节点、树实体与owner关系、工作进度、已发放状态、掉落/携带/工地容器，以及seed与生成版本。只保存库存总数不足以证明跨层采收不会复制资源。

## 9. 最小验收与尚未覆盖项

对照08的V01–V09，本资源切片至少需要这些可观察结果：
