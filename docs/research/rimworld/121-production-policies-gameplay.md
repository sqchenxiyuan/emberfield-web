# 生产分工与原料：把账单设置连接到实际加工

更新：2026-11-04。继续以玩法和机制为先，制作成本、速度和概率后续统一调整。原版依据见[120 生产分工与原料机制](120-production-policies-mechanisms.md)，上一阶段账单队列见[119](119-production-bills-gameplay.md)。

## 玩家操作与结果

每张账单的“分工与原料”可选择任意工人或指定殖民者。任意工人接受对应技能的上下限筛选；指定工人绕过玩家设置的技能区间，仍须启用对应分工并满足配方本身的技能要求。角色死亡或离开营地后，账单恢复为任意工人并提示原因。

取料可不限距离，或限制工作台周围的三维直线半径。楼层高度计入距离；原料实际堆放位置决定是否在范围内，货架旁的取货站位不会把范围外的物资变成可用。距离合格仍需有可走的通路。

烹饪可分别允许生粮和肉，屠宰可按兔、鹿筛选；取消全部选项后等待材料。木材燃料、布、钢材、岩块等现有固定配方槽不能通过食材筛选取消，取料范围仍对它们生效。不符合该工人条件的空闲账单允许后面的可做订单开工，已经投入的批次保留。

> 以下是v40历史行为；v41已为13条装备配方加入独立未完成品，暂停/删除后的行为见[123](123-unfinished-production-gameplay.md)。

## 修改、中断与恢复

第一次领取批次时保存原料策略。取料途中或加工中修改筛选和半径，不会更换当前批次的原料或凭空退料；当前执行者继续工作。当前批次完成后，新批次使用最新设置。如果途中因需要、征召或读档重新派工，接手人必须满足账单现在的工人条件，同时继续使用该批次保存的原料规则。

暂停或删除账单仍走实物退料流程，不受新筛选的阻碍。产物真正落地后才扣次数与耗材。没有加入独立的未完成物品实体，当前取消仍按上一阶段逻辑退料；原版 UFT 作者、剩余工量和半成品搬运留待后续。

携料取消时，附近有空间就放下完整原料；地面满时仍留在原工人手中，不能丢失。改变工人后，失去资格的携料者在没有仓位时也会尝试安全放料，供其他工人接手。搬运途中保存会保留合法输入与原作业的关联：读档重新检查工人资格和通路，不把绕路途中的人物位置误当成新的取料来源。

## 数据与三维适配

存档升级 **v40**。账单保存工人、技能范围、取料半径和筛选，已领取作业保存独立的原料策略副本。命令对象会复制，避免外部修改数组串改其他账单。旧档补默认策略，保留原有实物、队列身份和加工进度；当前格式缺字段、非法引用或把生产字段塞入其他作业会拒绝。

原版地面取料使用以工作台位置为中心的水平距离且严格小于半径；容器搜索另有包含边界的分支。原版滑条保存浮点值，界面以整数样式显示，最大端映射为不限距离。Web 明确采用统一的三维严格小于判定、3～100整数半径和单独的不限距离选项。这是多层世界的交互选择，并非逐字复刻原版滑条和容器边界。

实现集中在 [productionPolicies.ts](../../../src/voxel/productionPolicies.ts)、[productionBills.ts](../../../src/voxel/productionBills.ts)、[world.ts](../../../src/voxel/world.ts)及[生产面板](../../../src/voxel/ProductionBillsPanel.tsx)。更多可替代材料、成品品质/耐久筛选、仅统计某储存组和指定成品仓库尚待实现。

## 验证方式

- 模型与集成：`tests/voxel-production-policies-model.test.ts`、`tests/voxel-production-policies-integration.test.ts`。受控地形和物资注入明确限定为边界测试，覆盖跨层距离、货架锚点、硬技能门槛、当前批次保留、新工人接手、退料与命令隔离。
- 历史存档：保留真实 v39 加工中检查点的原始字节和 SHA-256；验证材料、人物库存、账单身份和工作进度迁移后可继续完成。
- 普通经营：`scripts/voxel-production-policies-campaign-verify.mjs`，从三份独立历史经营检查点分别继续制作、烹饪与屠宰，只用普通命令、模拟推进和保存恢复；逐 tick、逐命令审计资源账本。三条分支不冒充一座连续营地。
- 浏览器：`scripts/voxel-production-policies-browser-verify.mjs`，通过可见控件修改分工与原料并观察真实产出，Worker 与主线程分别验证。桥接仅用于读状态、投影和存档检查。

发布流水线继续只安装依赖、类型检查/构建和部署，测试在本地运行。

## 本轮验证结果

- 生产账单与策略四个文件共 **69 项**通过；新增策略模型 11 项、集成 18 项，包含实际绕墙走出半径后携料读档并完成的用例。
- 全量本地运行覆盖 **107 个文件、1365 项**，初次为 1360 通过、5 失败。两处人工准备批次的旧夹具缺少 v40 原料策略，另两处旧断言要求暂停后继续持料；补齐夹具，并把退料断言改为检查落地原料完整性后，四个文件 **72 项复测全部通过**。其余 103 个文件沿用同一运行时代码的通过结果；原始失败报告和复测报告分别保留，不把它们改写为一次全绿运行。
- 普通经营三条独立分支共 **377 条成功命令、15 项检查、11 份检查点**：制作从 v39/tick1795 到3379，做饭从 v30/tick150365 到151046，屠宰从 v31/tick28911 到29743。完成两件木棒、两份餐食及一具尸体加工；每条命令与每个 tick 后核对物资账本。
- Chrome Worker 与主线程各 **12 项检查**通过，页面和控制台错误均为0。通过可见控件和导入/导出完成工人、技能、半径、食材、尸体筛选以及三类实物产出检查；导入加工检查点后先实际续作，再检查修改时保留当前工人，读档后允许符合新条件的人重新接手。1440×960和980×720的控件、滚动与提示已检查，页面脚本和样式与最终本地构建一致。
- 类型检查与生产构建通过；源资料和文档链接检查通过。新原版静态/运行采集器的三项 `-Check` 均通过。

原版运行只对旧 playerForced 切石作业调高技能区间后继续工作作了实际推进观察；指定人、半径和空筛选的后续比较是右键派工菜单的可用性，没有执行新任务或完成远程搬料。普通保存—加载—再保存确认完整账单 XML 保留，世界前进1 tick。详细局限、原始哈希和裁剪见[120](120-production-policies-mechanisms.md)，不把 Web 的完整生产测试冒充原版实测。
