# 动物医疗：受伤、救助、护理与恢复

本轮按「玩法与机制优先、数值后调」补齐动物生存链。原版依据见 [151 静态机制](151-animal-medical-mechanisms.md)；下文描述独立 Web 实现，不把派生 C# 当作原始源码或运行证明。

## 如何使用

1. 在「动物 → 医疗」放置动物医疗睡眠点。它是一格、零建材的专用地面标记，需要有支撑、可达的空地；不能与设施、梯子或施工计划重叠。地面物品、仓储和农田不会被删除。
2. 给至少一名殖民者开启「医护」。医生会取真实草药，走到患者旁工作；没有可达草药时可以无药护理。「不接受护理」「无药护理」「草药护理」可逐只设置。
3. 受伤动物会出现伤口、疼痛与失血。严重伤情、失血或营养不良会导致倒地，不能继续游荡、求偶、牵引或接受普通饲养任务。可走路的患者会尝试沿动物自己的地面通路前往医疗睡眠点。
4. 医生优先处理出血，再救助仍倒地的动物。救助者实际靠近、抱起、沿人物通路搬运、放下；可以跨楼层搬到有梯子可达的病区。动物自己走路仍不能使用梯子或穿过关闭的围栏门。
5. 卧床患者饥饿时需要实际取食物喂食。医护和饲养分工都可以救助与喂食，伤口护理只由医护完成。医护会积累医疗技能经验。
6. 野生和商队患者默认不自动占用殖民地医疗劳动。可标记救助，或在详情里指定人员，成功开始后进入本次救助护理。动物的身份与派系保留，救助不是购买或驯服。

详情页展示具体伤口、护理质量、疼痛、失血与移动能力，以及谁正在取药、搬运或处理伤口。睡眠点可以定位和移除。护理止血后仍需时间恢复，不会立即补满生命。

## 机制连接

| 情况 | 当前行为 |
|---|---|
| 狩猎或流弹命中 | 形成独立伤口并扣除生命；身体部位影响移动，出血与疼痛可使动物倒地 |
| 护理 | 每次实际工作处理一处伤口；用药时消耗携带的一份草药，护理后停止该伤口出血 |
| 自然恢复 | 新伤逐步愈合；护理质量与卧床影响速度，失血在止血后逐步恢复 |
| 旧档只有生命缺口 | 不伪造旧伤部位或出血史；旧缺口可通过新增睡眠点卧床恢复 |
| 营养不良 | 饥饿与营养不良继续运行；喂食增加真实营养，营养不良随后逐步消退 |
| 预约 | 同一患者只有一名照料者，同一床只分配一个患者，药食与现有搬运/生产预约共享真实库存 |
| 征召、死亡、断路或撤床 | 中断任务，搬运动物留在搬运者位置，携带药食保留；不复制或删除动物 |
| 物品禁止、贸易转移预留物资 | 原预留任务撤销，未使用药食不计入消耗 |
| 贸易 | 站立伤兽的伤口/失血随同一ID转移；倒地或搬运中的动物不可直接交易，照料指派随交易取消 |
| 死亡 | 清理护理/床位/搬运关系，仍进入原有唯一尸体与屠宰物流 |
| 繁殖与生物产品 | 医疗期间仍更新饥饿、年龄、已有妊娠和产物进度；控制移动期间不进行交配或现场产蛋 |

## 明确的适配与后续边界

- 目前采用躯干、头部和行走肢体的紧凑模型；鸡有两条腿，其他四种有四条腿。没有把人类手臂、64部位人体结构强套到动物身上，也没有声称完整实现原版器官、缺肢、致命器官伤、手术和疾病系统。
- 尚无动物伤口感染、兽医手术、义肢、药物等级全集、医疗床品质/舒适度、按体型限制的睡眠箱。当前专用睡眠点服务五种已实现动物。
- 伤害仍来自当前接入的狩猎/流弹路径；没有借本轮宣称完整动物火灾、温度伤、捕食、近战或疾病伤害模型。
- 原版动物护理使用真实 Pawn 健康系统和更复杂的伤口分批。Web 每次处理一处伤口、一次用一份药，出血/疼痛阈值与疗程集中在 `animalMedical.ts`，以后再校准。
- Web 使用逐 tick 连续恢复，饥饿时显著减慢；原版普通自然/已包扎恢复按间隔采样，饥饿时会中断。当前睡眠点恢复倍率也属于 Web 调整，不等同原版地面睡眠点具有家具治疗加成。
- Web 把严重出血护理放在搬运前，也允许饲养分工参与救助；原版自动救助属于 Doctor。当前「不接受护理」只禁止处理伤口，仍允许救助/喂食，与原版部分救助入口的 NoCare 检查有区别。
- 原版标准商队 Lord 会移除倒地成员。Web 保留商队的个体归属记录，以便恢复后接续撤离，这是独立连续性设计。
- 不实现原版随机倒地即死亡机制。五种当前 Core 动物的训练能力为 None，不满足原版护理 Bond 随机招募分支的最低训练能力。
- 暂不为存量旧伤补发病历；正常旧世界在未设置新的睡眠点且没有新增伤情时维持历史行为。

## 存档与验证

v54 保存动物伤口、局部伤口ID、失血、护理政策、床位、携带者以及医生任务阶段、物资预约和工作进度。迁移只增加默认医疗状态与空床位列表，保留动物原生命和交易回执。历史快照是历史记录，不会注册第二只活体；伤口ID属于该动物的局部命名空间。

新档检查身体布局、数值有限性、伤口与生命缺口、床位唯一性、搬运动物与护理者的双向关联、阶段和实际物资。无界面测试覆盖完整护理物流、治疗后恢复、分工、无药政策、物品禁止、撤床/征召中断，以及读档与交易。

最终验证输入与结果冻结到 [animal-medical-voxel-validation.json](evidence/animal-medical-voxel-validation.json)。测试、SSR和 Three.js 几何检查均不启动浏览器或 GPU；未进行原版程序交互、屏幕手感或长期经营验收。

本地完整回归覆盖 143 个测试文件、1,880 项检查。首轮 1,877 项通过，另有一项建造测试超出原有 5 秒时限、两项旧驯养迁移测试未区分新增医疗字段的专属校验器。更新两项测试的字段归属与精确报错预期后，单独重跑相关三个完整文件，35 项全部通过；建造用例在原时限内完成，未改游戏逻辑或放宽超时。冻结记录保留首轮及修正后的报告，按各文件最新完整结果汇总为 1,880 项通过。

生产构建 `npm run build`（TypeScript 检查与 Vite 打包）通过；构建日志和产物哈希一并冻结。Vite 仍提示部分压缩后模块超过 500 kB，这是现有体积提示，不代表本轮测过首次加载体验。

真实 v53 检查点来自已发布 Git 版本，未注入命令或改写旧状态。原模型和 v54 共续跑 750 ticks、5 次回读、756 次完整状态比较；只标准化版本及已断言为空的床位/默认医疗字段，旧生产、物资、随机状态与动物行为一致，完成 1 份简餐和 1 顶布帽。它证明旧档连续性，不代替新版长期医疗经营验收。

GitHub Pages 继续只安装、构建和部署；测试只在本地运行。原版程序集、完整派生代码、美术与原版存档不发布到仓库。
