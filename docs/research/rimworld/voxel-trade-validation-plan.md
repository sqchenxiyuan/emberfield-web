## 验收前必须明确的实现契约

1. 银币的存储形式、初始来源和 v20 迁移规则；若新开局赠予银币，必须与后续售货收入分开记录。旧档迁移补什么以及为什么必须明确，不能默默靠补资源使测试通过。
2. 商队入场、可交易、离场的实际条件，现有存档迁移时的下一次机会，离场后库存与装备的归属；新旧存档是否共享同一日历与随机规则。
3. 报价选择的物品范围：地面/仓储、人物正在携带、已交工地、穿戴装备、敌人或商人持有物分别如何处理；明确距离、可达性与谈判者要求。
4. 报价中基础市值、商品买卖系数、难度、谈判修正、品质/耐久、最终单价、订单总额与银币取整的实际步骤。第 04 章旧研究只是线索，应以本轮原版证据和最终复刻设计为准。
5. 成交的提交与失效契约：报价刷新、库存变化、旧报价、重复提交、资金不足和商队离场时是否整单拒绝；银币与货物何时真正转移。
6. 食物批次如何拆分/合并及保存腐坏年龄，装备交易是否保持原始 ID/品质/耐久，交易记录、进出口账本和存档迁移字段如何表达。
7. 快照只读字段、普通游戏命令、可见 UI 控件及导入导出方式。观察接口可以读取真实状态，不能拿内部 setter 构造验收结果。

## 独立普通经营流程

正式流程从固定种子的新营地开始；若复用 v20 营地正常迁移，必须单列为迁移继续流程，不能冒充从零经营。实际执行脚本、游戏 bundle、源文件清单和原始存档均冻结。开发失败保留错误、终点和来源，正式继续仅从同源实际终点正常 load，禁止回溯刷商队库存或价格。

1. 用普通施工、种植、伐木/采矿和工作安排建立粮食与生产。至少完成一件本轮实际生产的可售商品，记录原材料消耗、生产任务、产品实际产出及可观察身份，不能只卖初始赠品证明生产贸易循环。
2. 正常推进直到真正商队出现并满足交易条件。记录实际入场 tick、商队身份、库存、资金、到访与离场状态。不得 spawn 商队、改 nextArrival、推进时钟变量或替换随机种子。
3. 对真实库存获取并核对报价。记录商品、数量、来源批次/装备、报价组成和总额；同一 tick 的只读报价不能改写库存、银币或装备归属。
4. 完成至少一次售出实际生产商品和一次买入实际商品。交易前后逐项核对殖民地与商队双方库存、银币、装备 ID、食物批次/年龄、nextId 和账本；若采用以物易物净额结算，需明确两侧货流和净银币结果。
5. 普通运输/使用至少一件购入商品，证明买到的是可参与实际模拟的物资。食物交易需保留年龄并在正常时间中继续腐坏，装备交易需真实落地/搬运/装备且身份唯一。
6. 保存并正常读回交易前、成交后、商队尚在场和已经离场等实际检查点。重载不得重复结算、补货、赠银币或重新抽签；存档内进行中的生产、医疗和袭击日历不应因贸易迁移损坏。
7. 正常观察商队离场或会话失效。按确认的原版契约，商人在入场和离开途中仍可交谈；条件由人物能力、距离、关系和实际存在决定，不能仅因 `stage=leaving` 就宣称交易已经失效。实际离图后旧会话不能继续成交。若最终实现仅支持其中一部分，应在覆盖表标为未覆盖，不能用规则测试替代经营中实际发生的结果。

物资账本按资源分别核对：

`期末 = 期初 + 生产 - 消耗 - 腐坏 - 损毁 + 买入 - 卖出 + 其他明确的外部转移`

入场袭击者/商人携带物、人物死亡掉落和贸易不能同时算作“生产”。人物携带、已交施工材料及其食物年龄记录只算一份物资。银币交易不凭总财富差验证，因为买卖价差会真实改变殖民地估值；检查双方实际银币增减及明确的交易费用/取整差额。

同一 tick 结算时，售出的食物批次年龄应原样转移；若正常时间已流逝，按实际时间/温度规则核对，不能错误要求年龄永不变化。装备的归属从卖方转至买方，ID、品质与耐久不能通过交易或回读重置。若支持回购，同一会话的正常买卖不得无成本获利。

## 独立规则与事务检查

下列边界适合快速规则/集成测试；结果与普通经营覆盖分别报告，不把手工构造边界叫作真实商队过程。

- 买/卖价格和最终银币取整的边界值；品质、耐久和难度修正顺序；货币本身与普通商品的区别。预期值由独立算例计算，不能直接调用生产报价函数生成 expected。
- 负数、非整数、NaN/Infinity、超过库存、超过资金、同一装备重复出现在订单、已离场会话、陈旧报价与重复提交；失败不能部分扣货或扣银币。
- 成交前库存被吃掉、腐坏、搬走或用于生产；应按实际契约拒绝或重新核验，不能使用过期数量造成负库存。
- 穿戴、携带、已交工地、敌人物资和商人库存的交易可用范围；按声明限制验证，禁止顺带售出不属于玩家的物品。
- 食物批次拆分/合并时数量守恒且年龄语义保留；相同种类不同年龄不得无意全部变新。装备交易前后跨所有容器检验 ID 唯一。
- 成交后的保存/读回和继续运行：成交记录不重放、银币不重复发放、商队库存不刷新、下次到访不因每次读档重新生成。
- 七份真实 v20 样本全部迁移；对原有物理字段逐项比较，只允许文档列出的新字段和已知派生重建变化。尤其保留 `working` 的半成品、`carrying` 的食物年龄和 `scheduled` 的既有袭击机会。

## Worker 与 main 浏览器验收

两种渲染模式各自跑完整场景。使用真实文件选择器导入检查点、可见贸易入口/数量控件/确认按钮成交、实际导出按钮下载，再从下载文件正常回读。只读 snapshot、投影和存档导出用于观察；页面中注入 command、修改状态或直接调用交易提交方法不能算 UI 通过。

至少保留以下可见证据：

- 七份 v20 样本的真实导入，以及制作/携带/战斗/受伤/康复/待发生日历不丢失。
- 真实商队出现、可交易或不可交易原因、双方银币/库存、买卖方向、数量、单价与总额；报价和殖民地财富估值的用途可区分。
- 用可见控件实际售出一件普通经营产品、买入一件商品；成功后的双方余额与库存更新。
- 数量不合法或资金不足时有可理解提示且物资不减少；取消确认保持状态。
- 真实导出/导入后交易结果与商队状态保留；正常时间中商队离场/会话失效。
- 900×700 窗口下商品列表、方向/数量、总额与确认控件可见可操作，无遮挡或横向溢出。

生产预览服务实际发送的全部 JS/CSS 与本地冻结 dist 字节对照；记录 page/console 错误、执行脚本哈希、截图哈希及导入下载文件哈希。预检若仅覆盖准备阶段，须单列为 preliminary，不能计入完整贸易验收。

## 证据与失败处理

最终报告分开列出：独立规则测试、普通经营实际发生的贸易、旧存档兼容、Worker/main UI，以及原版静态/实机研究。每个通过数绑定本轮执行 bundle 和报告，旧 v20 的 675 项测试、91 项经营检查及 19+19 浏览器检查不自动成为 v21 结果。

所有未出现的事件、商品类型或交易路径明确列为局限。一次固定种子商队不证明长期供需平衡、所有库存组合或统计概率；如尚未实现谈判技能、派系商人差异、动物、囚犯、轨道交易或世界地图商队，验收不宣称这些功能存在。发现真实失败时保留检查点和原始报告，修改后是否继续或从头运行取决于失败原因与冻结源码变化，不能覆盖失败证据。
