# 17 多层电网、燃料与房间温度

更新：2026-11-03。[在线体素版](https://sqchenxiyuan.github.io/emberfield-web/?world=voxel)，[原版证据](16-power-thermal-mechanisms.md)。本章描述 Emberfield 的独立实现。原版仅实际观察了建筑信息面板，没有实测发电、补料或温度曲线，不能把本章测试当作原版动力学证明。

## 操作与数值

先砍树、下挖梯井，开凿钢矿和机械矿取得钢材、零件。设备需要完整地板支撑和两格净空；不能与床、门、树、灶台、区域或梯井重叠。每次放置一件，R 切换 X/Y 朝向。下方工具条可以横向滚动。点击设备检查燃料、储电、运行原因和电网供需，冷暖设备可设置 −50～50°C 目标。

| 设施 | 占地 / 材料 | 运行规则 |
|---|---|---|
| 木燃发电机 | 2×2；100钢、2零件 | 1000 W；容量75木燃料，每游戏日消耗22；开启且有燃料时空载也消耗；向所在房间散热6游戏热量单位/秒 |
| 太阳能板 | 4×4；100钢、3零件 | 最高1700 W × 天光 × 未遮挡面积比例；夜间不发电 |
| 电池 | 1×2，R旋转；70钢、2零件 | 600 Wd；充电效率50%，放电100%，自耗5 W；隔离后仍自放电 |
| 电线 | 每格1钢 | 六向相邻线路、电源设施占地相连；竖井逐层布线实现跨层供电 |
| 加热器 | 1×1；50钢、1零件 | 工作175 W，待机17.5 W；基础21热量单位/秒；20°C以上效率下降，120°C为零 |
| 冷气机 | 1×1；90钢、3零件 | 工作200 W，待机20 W；负轴蓝侧制冷、正轴橙侧排热；排热是可用制冷热量×1.25 |

发电机、太阳能和电池都是导电节点，即便没有输出也不切断网络。冷暖设备在同层13×13方形中找最近导体，没有视线检测；这包含对角角落，不能理解成半径6的圆。跨楼层必须连接真正的竖直电线，不会隔层无线接电。

发电机低于等于22.5燃料触发补料，目标为 `ceil(75−fuel)`，普通补料允许只使用当前可达的部分木材。木材实际搬到工作面，80工作tick后变为内部燃料；满量截到75，最后不足1单位的溢出不返还。内部燃料不计入营地木材库存，转换计入`consumed.wood`。取消未完成工作返还已送材料，搬运、睡眠中断与回读沿用现有材料账本。设备拆除返还材料的一半向下取整、发电机另返还整份剩余燃料；这是本项目拆除规则。

建造基础工作：发电机/太阳能834tick、电池267、加热器334、冷气机534、电线12；原版基础工作按20/60换算并向上取整，无技能、品质或施工失败。这里的1日仍是12000tick/600现实秒；电功率到Wd用每tick除以12000，燃料按游戏日消耗，工作与热输出按现实秒换算。这是明确的时间尺度选择，不等于原版60000tick/1000现实秒的一日。

## 电量与温控

电网每tick计算供需。多电池分摊输入/输出，满或空的电池退出后重新分配；输入扣除50%充电损耗，输出与自耗扣实际储能。没有功率上限、线路损耗、短路、雨淋损坏或EMP。

保留原版启动的5 Wd比较余量：存在启用电池且总储能≥0.1时，启动前先用`stored−5 + netGeneration/DAY >= 0`判定；候选负载再用未扣余量的储能判是否付得起。这不是实际扣除5 Wd。即使实时发电足够，少量储能也可能延迟启动。启动/卸载轮询换算到20TPS，候选使用确定性tick/id散列，未复刻原版随机序列。额外加入逐tick硬能量门槛：无法支付的设备立即断电，避免轮询间隔内凭空供热；这是本项目相对原版渐进切换的明确差异。

候选散列在取模前混合高低位，避免轮询间隔与候选数有公因数时反复跳过同一批设备。回归覆盖无电池、50 W太阳能与16台交替17.5/175 W负载：能启动两台待机负载，不能启动175 W负载；逐一把16个位置设为唯一可负担负载，也都能启动，且每tick实际功耗不超过发电量。

加热按目标温度截断热量。冷气机读取两侧温度，效率为 `max(0, 1−[hot−min(cold,40)]/130)`，可以大于1。两侧需要有效空气，堵住任一风口就待机；负侧抽热，正侧排热。保留原版“排热基于目标截断之前的可用热量”的特征。两个风口若通向同一空气组件，就会加热同一个空间；应该将冷气机装在分隔冷热房的墙上。冷气机本体占两格高，作为房间边界；其他电力设备不充当密封墙。

## 三维热模型及边界

空气六向连通，连接世界边缘即室外。室外沿用自定的昼夜14～28°C曲线；太阳光仍是本项目日间饱和曲线，没有原版纬度、季节、天气与事件。切换剖切高度不改变房间、温度或遮光。

每空气体素热容量0.5，让两格高房间的容量与地面格数相同。共享一格厚墙面每秒导热系数0.0102；更厚的天然岩土边界以0.0051系数连接15°C地温库，木结构厚边界连接室外。15°C地温库是**双向**交换，属于本项目三维扩展；原版厚屋顶的15°C冷却规则并不等价。

门按四个水平方向去重后的房间均温交换，开门速率60/34、关门60/375热量单位/秒/度；门的朝向不影响取邻居。连续热交换与稳定子步代替原版离散hash调度。一次子步的所有热流使用同一旧温度，室内相互交换等量反向，分别核算室外与地温库输入，避免按遍历顺序产生热量。

拆墙、封口或新挖空间后按重叠空气容量迁移温度：分裂保温，合并按实际重叠热容量加权，新空气以室外温度加入。原版特殊重建路径使用完整旧房间面积加权，不能声称与此一致。保存每个室内房间的锚点和温度，不把易变的roomId当永久身份。温度范围−273.15～1000°C。

室温已经进入作物的生长温度判定。没有低温/高温伤害、舒适心情、睡眠温度惩罚、食品腐坏、温室灯、通风机或完整气候系统；设备“开着”不能作为这些系统已实现的证据。

## 工程与内存

`power.ts`负责网络及电量，`thermal.ts`负责房间热容量、交换图和迁移，`world.ts`负责物理建造、补料与每tick连接。React只发命令，模拟Worker发布摘要，Three.js渲染Worker/主线程兼容路径显示设备、线路、旋转蓝图和运行反馈。动画时间来自逻辑tick，暂停冻结。

电网固定工作数组576 KiB，房间拓扑576 KiB，热模型持有256 KiB房间ID副本及随房间/交换边增长的小数组。热图只在地形/门/冷机边界变化时重建，平常只遍历缓存。单地图最多256设备、4096电线，规划最多512项。计数不包括JS对象、临时重建、整页或GPU驱动内存，未测试4 GiB极限。

存档升到v4，v1/v2/v3逐级迁移。燃料小数、储电小数和室温保留；路径/预定和电网连接重建。设备种类、范围、占地、重叠、材料、热记录及坐标在替换运行世界之前校验。施工不能埋住物资；只有所有物资都能挪到同层相邻合法格才提交。拆楼板/梯子还会检查原先可返回营地的人物与物资是否仍可返回，防止保留脚下支撑却切断唯一出口。

## 复现与验证

```sh
npm test
npm run research:check
npm run test:voxel:power
npm run test:voxel:housing
npm run test:voxel:food
npm run build
# 在已运行预览服务器上验证；支持 VOXEL_TEST_URL
npm run test:voxel:power:browser
```

正常流程脚本`voxel-power-campaign-verify.mjs`只使用`command/step/save/load`，会读取生成地形来选择矿脉，不注入材料、设备、燃料、温度、精力或时间。它先伐木、开梯井、挖有限钢矿及机械矿，封闭两个地下房间，再建五种设备与跨层线路；测试热房、断线/修线、定向制冷/排热、电池独立供电、全部电源关闭、v4恢复，以及真实二层楼板遮挡太阳能和正常拆除后恢复。每20tick检查物资守恒与人物支撑，重要检查点再检查一次。它是加速执行逻辑tick的Node流程，不是数小时原版或浏览器实机观察。

本次流程在tick14944将冷房加热到30.06°C，电池存储约55.63 Wd；tick15599制冷至10.00°C以下，排热室由26.07°C升至63.53°C。夹断竖井Z6的一格电线会断掉地下设备供电，修线后恢复。最终tick27044完成遮光/拆顶流程，营地仍有48口粮、55木材；累计用掉419钢材和11零件。确切脚本、测试、浏览器报告与资产哈希以[evidence/voxel-power-validation.json](evidence/voxel-power-validation.json)为准。

单元测试另使用明确标注的隔离fixture，覆盖能量守恒、启动边界、多个电池、两轴冷机、目标截断、太阳能逐格遮挡、房间迁移、稳定导热、恶意存档和施工回滚。隔离fixture不计作正常采矿建造证据。浏览器验收使用上述流程生成的存档，通过真实DOM、鼠标、键盘和文件选择器操作，同时检查Worker与主线程渲染；只读调试API仅用于投影、导出及断言。

最终191项单元测试全部通过；电力浏览器Worker/main各12组检查，涵盖24格设备占地拾取、16个窄屏控件和运行中冷气机暂停0像素变化。住房存档浏览器回归两路径各5组，食物浏览器11组通过；三层施工、住房、17.23游戏日的两轮稻米流程、二维完整营地及两种子动物运动也通过。以上浏览器资源均核对为同一生产构建，详细边界与哈希在验收记录中。
