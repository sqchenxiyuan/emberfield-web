# 96 房间生活、实体用餐与舒适

本轮以可操作的生活闭环为目标：玩家建设空间和家具，居民实际使用，需求与心情产生反馈。桌椅成本、进食时长和睡眠触发门槛使用集中定义的初步参数，不作为最终平衡。原版静态与实机证据分别见[94机制研究](94-dining-comfort-mechanisms.md)、[95实机对照](95-native-dining-runtime.md)。

## 玩家操作

1. 在建筑菜单放置2×1木餐桌，用R切换朝向；在同层餐桌四周紧邻放置餐椅，留出走到椅子的路线。
2. 居民饥饿后寻找真实食物，拿走本餐份量，预约可达的空闲餐椅，携餐步行过去并坐下。动画与进食进度持续到这顿饭完成，随后才增加饱食度。
3. 没有合适座位时就地吃饭。原地紧邻餐桌可以站在桌边吃；独立椅子不会被当作用餐座位。生粮和肉仍可应急食用，保留既有生食影响。
4. 选择居民可查看舒适度、正在取餐/就座/进食的状态，以及用餐和居住记忆。选择桌椅可查看相邻座位、预约者并拆除；选择房间内格位可查看用途、空间、财富、美观与清洁。
5. 建立有床的封闭房间、指定床主并安排睡眠。实际卧床提高舒适，睡够一段时间才评价卧室或宿舍，醒来后记忆继续保留一段时间。病床和囚犯床也提供实际卧床舒适，不冒充普通卧室记忆。

## 行为与物品状态

| 环节 | 实际机制 |
| --- | --- |
| 取餐 | 使用现有物资与可用量，食品批次携带年龄、耐久和污染信息；没有独立虚拟餐食库存 |
| 选座 | 同层餐桌四邻、可站立、路径可达、路程在范围内、座位未被他人预约或占用；候选按距离排序 |
| 预约 | 从前往座位开始占用餐椅；一桌可供不同椅子的多名居民同时使用 |
| 用餐 | 人物抵达目标才咀嚼；身体进食能力影响进度；完成时一次扣食物、恢复营养并产生记忆 |
| 无法卸货 | 非食品货物无处放下时保留原货物，预约脚下食物进行原地用餐；不会删除货物腾手 |
| 中断 | 征召、疾病、搬移、桌椅拆除、火灾或路径失效会释放任务/座位，仍携带的餐食保留 |
| 腐坏与销毁 | 食物仍按所在温度腐坏；食物失效会取消用餐，不能再获得营养或重复消费 |
| 回读 | 保存携带批次、用餐阶段与进度；重新验证家具、食物及路径；失效任务安全取消 |

无桌记忆在完成需要餐桌的餐食后产生，同类记忆刷新而不叠加。后来用餐有桌子不会立即抹去先前的无桌记忆。封闭房间中的用餐评价按当前房间印象读取，不要求房间角色名字一定是“餐厅”。

## 房间如何影响生活

房间拓扑来自真实三维连通空间，剖切视图不改变房间。用途由现有家具派生：普通床形成卧室或宿舍，医疗床和囚犯床另行分类，没有床但有桌的空间可成为餐厅。当前没有亲属与双人床系统，一张普通床算卧室，多张算宿舍。

房间统计复用现有卫生模型，并结合可用空间、铺装、建筑和家具估值、美观与污物。地面物品堆及人物财富不直接充当房间财富。空间与面积分开，不能用连通空气体素数量代替可使用地面。房间ID会随分隔或合并改变，评分和用途只在运行时派生，不作为持久身份保存。

昂贵的地面扫描按房间拓扑缓存并共享给所有人物；家具和污物在实际查看或生活事件时聚合。新增需求与记忆采用有界记录，未新增全地图逐人物扫描或第二份世界。

## 与原版的边界

- 复用的是取食、寻座、咀嚼、消费、记忆以及舒适需求的联系。Web保持20 TPS、12,000 tick/天，渲染独立于模拟。
- 首批家具只有木桌和木椅，没有家具品质、多种材料、高级座椅、雕塑或完整房间美观对象库。
- 桌体在Web中阻挡通行；餐椅可通行，桌椅格不能作为地面仓储。原版座位评分、路径成本及所有家具通行细节没有完整照搬。
- 舒适从实际床/椅接触向目标变化。睡眠使用确定性门槛替代原版随机首次评价时刻；房间财富/美观的实体覆盖是本项目子集。
- 原版用餐评价读取所在房间印象，没有显式的室内限制；Web本轮只对封闭房间生成用餐环境记忆，这是简化规则。
- 普通殖民者的自主吃饭进入新流程。医护喂食、囚犯供餐和商队生活仍沿用各自已实现子系统，尚未统一成全部原版进食Job。
- 实机验证只支持所记录的行为分支，不证明原版所有房间档位、进食能力或概率已做运行校准。

## 本地验证与发布

局部机制测试覆盖真实材料建造、两格桌体、座位竞争、行走与咀嚼分离、打断保留餐食、火毁座椅、腐坏、生活记忆和途中回读；另有原样保留的真实v30存档迁移验证。

普通经营脚本从未经编辑的新开局执行伐木、建造、开凿、生产餐食和生活活动，浏览器脚本检查Worker及主线程渲染路径。验证命令：

```sh
npm test
npm run build
npm run test:voxel:living
npm run test:voxel:living:browser
```

本轮本地通过1041项测试（76个文件）、41项普通经营检查，以及Worker和主线程两种渲染模式各14项浏览器检查。普通经营推进至tick 34,439，覆盖从新开局建设、生产到实际用餐、睡眠评价和拆除预约座位。运行身份和产物哈希记录在[验证证据](evidence/voxel-living-validation.json)。测试仅在本地运行，Pages流水线继续只安装依赖、检查类型、构建与部署。
