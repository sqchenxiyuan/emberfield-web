# 制作完成后的仓储去向

更新：2026-11-04。v42 接通“制作完成 → 成品携带 → 实际送达”的流程，继续以玩法和机制完整为先。速度、容量和经济平衡沿用可调整参数。原版证据见[124 成品去向机制](124-production-output-mechanisms.md)。

## 玩家操作

生产账单新增独立的“成品去向”：

| 去向 | 行为 |
|---|---|
| 就地放下 | 成品放在制作者附近，之后由搬运工收纳 |
| 送往最佳仓库 | 制作者选择接纳产物、可达且有空位的仓储，先比较优先级，再比较路径成本 |
| 送往指定仓库 | 选择有名称的地面区域、单个货架或联动储存组；不会因为其他仓库优先级更高而改变目标 |

点击“指定仓库”后，选好具体目标才提交设置；此前原设置继续生效。选择器合并联动货架的成员，避免同一个组重复出现。已选目标满仓或不再接纳成品时保留设置；实际完工时找不到合法仓位则放在附近。

联动组的货架全部卸下后，只要组身份仍在，账单保留目标，暂时按无仓位处理；重新装回后可继续接纳。单独指定的一座货架被卸下则撤销该目标。

选择地面仓储可以改名或扩展。区域有稳定身份，改名、扩展、擦除一部分都不会使账单丢失目的地；最后一个成员消失时才撤销该引用。区域身份与原有逐格筛选相互独立，相邻的两个区不会自动合并，原有“连片设置”仍按几何连通选择格子。

送货由制作者直接执行，不要求启用“搬运”分工。人物详情显示正在运送的成品及目标，可定位仓库。只携带第一种产品的一次携带量，其余产物留在工作位置附近；该行为不会顺带抓取旁边已有的同类物资。

## 完工、中断与保存

原料消耗、实体成品生成和账单完成次数一起结算。送货属于完成后的独立活动：修改或删除账单不会重做产品，修改去向也不会改变已经开始的配送。库存目标的计数范围独立于成品去向。

送货前及放入时重新检查通路、筛选、剩余容量和目标成员。目标失效时中止送货并尝试就近放下。附近没有空间则保留人物手里的实体成品和等待落地状态；不会丢失物资，也不会重复结算生产。征召、睡眠、医疗等人物活动仍可打断配送；实物继续由既有携带与物资系统持有。

存档格式为 **v42**，持久化区域身份、账单去向和配送意图。货物只存在于 `pawn.cargo`，配送意图不保存货物副本或生产工量。载入时验证字段及身份并重建通路和预定；历史账单已经被删除的已完成配送仍可恢复。

旧档升级保留原来的就地生产行为，显式旧账单迁移为 Drop；未改用账单队列的旧式工作台默认适配器也保持 Drop。新添加的独立账单默认 Best。历史地面仓储按同层、相邻且规则相同划分为有身份的区域，不改原有筛选、优先级或物资。

## 与原版的边界

- 原版默认 Best，生产完成计次后再由制作者携带产物列表中的首个实体，指定目的地与目标数量统计范围分开。Web 当前配方输出按资源批次组织，运送第一个输出批次。
- 原版新建的搬运任务启用 `haulOpportunisticDuplicates`。Web 只运送这次生成的指定批次，不顺带拾取同类旧物资；这是明确的行为适配。
- 原版放置失败存在再次寻找最佳仓储或挪开货物的细分分支。Web 对运输目的地失效统一采用附近落地、满地保留携带的处理，不能声称逐分支一致。
- Web 先预定目标能容纳的数量，携带量同时受该剩余容量和人物上限约束；原版会先按人物上限携带，再由放置流程处理目标放不下的余量。
- Web 同优先级仓位按三维路径成本比较；原版该搜索按水平距离平方并允许提前结束，不能把两者称为相同寻路算法。
- Web 区域可以包含不同的逐格规则，并允许擦除后保留不连通成员；原版区域设置方式不同。这里优先兼容已有 Web 仓储操作与存档。
- Web 暂按接纳第一种产物筛选可选目标；目标是否满仓或可达在实际完工时判断，不把 UI 列出目标等同于保证能送达。
- 此轮没有新增跨地图物流、远程传送、储存容器嵌套或经济平衡调整。
