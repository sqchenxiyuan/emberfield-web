# 生产账单：玩家安排、实物加工与中断恢复

更新：2026-11-04。本轮继续按“玩法与机制优先，数值后调”推进。原版依据见 [118 生产账单机制](118-production-bills-mechanisms.md)；本页区分 Web 实现与原版差异，不把静态派生证据当成运行证明。

## 可玩的生产管理

灶台、屠宰点、切石台、裁缝台、制作点、锻造台和机械加工台共用账单面板。玩家可以添加同配方的多张账单，逐张设置“制作指定次数”“持续制作”“维持库存目标”，上下调整顺序，暂停、恢复或删除。武器与护甲在同一个工作台队列中排序。

- 每张账单都有稳定身份。在制任务绑定身份而非列表位置；重排、模式切换和降低目标保留已经选中的当前批次。
- 次数只有在产物成功放下、耗材提交后才减一。归零账单保留供再次启用。没有产物落地空间时，保留材料、完成进度和品质结果，重试不重复扣次数。
- 手动暂停与自动库存等待分离。前者中断加工并退料；后者达到目标时进入等待，实物库存降到恢复线或更少再补产。自动等待和剩余次数均可保存。
- 尚未投入材料、没有工作进度且无人执行的不可做账单，可让位给后面的可做配方；材料不够或没有合格工人不会永久霸占队列。已经投入的批次保留，等补料或玩家处理。
- 删除与暂停走既有实物退料流程。退料位置满时，材料保留在取消任务的有限容器中，等待腾空；删除账单不会清空材料。空账单队列在保存恢复后仍为空。

模型集中在 [productionBills.ts](../../../src/voxel/productionBills.ts)，实际派工、退料、完工事务在 [world.ts](../../../src/voxel/world.ts)，交互在 [ProductionBillsPanel.tsx](../../../src/voxel/ProductionBillsPanel.tsx)。调度每轮缓存同配方库存和在制量，避免逐工作台重复扫描全部物资。每台至多32张账单是当前防护上限，不是原版平衡参数。

## 存档与兼容入口

格式升级为 **v39**。v38及更早存档保持原配方目标、暂停状态、材料和在制进度，默认账单使用可重建的稳定身份；第一次编辑队列时转成显式账单。显式空队列不会回退成默认配方。旧 SDK 的 `bill`、`stoneBill`、`tailorBill`、`weaponBill`、`armorBill`、`butcherBill` 继续可用，对已经管理的队列只更新首张匹配配方；新交互按账单ID操作。

当前格式严格检查队列上限、配方归属、账单身份、阈值、作业关联及对象身份冲突；旧格式夹带新账单字段会拒绝。测试保留上一轮普通经营产生的真实 [v38 原始检查点](../../../tests/fixtures/voxel-v38-before-production-bills.json)和 [来源校验](../../../tests/fixtures/voxel-v38-before-production-bills.provenance.json)，不修改历史字节来伪造迁移。

## 原版与当前适配边界

原版使用不同的资源/非资源/储存组/石砖计数路径，默认不计装备，也不预先计入未来产出。Web 本轮保留既有的全营地实物统计（包括穿戴、装备、携带）并估算在制产量以减少重复补产；迟滞只由实物触发。固定批量可能跨过目标；屠宰在尸体运达前按可处理种类的最小产肉量估算。不能把这套目标数量解释成原版 ResourceCounter 的完全复现。

Web 尚无独立的未完成物品 UFT：中断加工会退回实物原料，重新开工重新加工；原版有些长配方会留下带作者、材料和剩余工量的 UFT。原料筛选/半径、指定工人、技能上下限、成品品质/耐久筛选、仅统计特定储存组及目的仓库仍留待后续。工作台跨层通路继续由现有三维寻路处理。

机制测试：`tests/voxel-production-bills-model.test.ts` 与 `tests/voxel-production-bills-integration.test.ts`；普通经营：`scripts/voxel-production-bills-campaign-verify.mjs`；浏览器：`scripts/voxel-production-bills-browser-verify.mjs`。

普通经营从真实v38营地继续，经普通伐木、建设、账单命令和模拟时间取得材料与产物，每tick审计资源账本。定点边界测试另用明确标注的受控地形和材料，不能当作自然经营证据。发布流水线继续只安装依赖、类型检查/构建和部署，测试留在本地。

- 普通经营脚本：32条成功命令、10项检查、3份带SHA-256的检查点，从tick490继续到3675；两次指定生产加一次持续生产均落成实物。每tick与每条命令后校验资源账本。

### 原版运行对照

本轮在RimWorld 1.7.4980 rev60、Core + Odyssey的独立资料目录中，以历史石工台实验存档为基线，通过普通界面操作保存三个新阶段；详见[118运行记录](118-production-bills-mechanisms.md)和[结构化证据](evidence/native-production-bills-runtime.json)。基线历史上使用开发工具准备工作台、材料与需求，本轮没有修改存档或注入状态。截图与只读XML共同辅助观察，不属于纯看屏幕实验。

实际确认：暂停打断正在加工的DoBill而不扣次数；一批20石砖落地后，次数从1变0且账单保留；同配方三张账单能分别配置次数、持续、库存目标并重排。目标10、恢复5只确认配置与序列化，**没有实测库存消耗触发的完整迟滞循环**。第二份存档记录的是中间搬料，不证明暂停后工量保留或重置；三个新存档未重新载入，不能将保存证据写成读档验证。原版进程已正常退出。
