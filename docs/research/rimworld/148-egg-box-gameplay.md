# 蛋箱玩法：集中产蛋与实际收运

v52 继续按「玩法链路、操作反馈、异常恢复、旧档连续性」推进。建造、收蛋速度和造价暂用集中配置，后续统一平衡。原版依据见 [147 静态机制](147-egg-box-mechanisms.md)，不把 Web 参数当作完整的原版复现。

## 玩家可以做什么

在建造菜单选择蛋箱，在有支撑和净空的地板上放置单格计划。工人需要搬来真实木材并完成施工。蛋箱可走过，允许建在木桥上；不能与墙、梯子、其它设施或地面仓库重叠，也不会成为房间或圈地的边界。

准备产蛋的殖民地母鸡优先寻找可达、未禁止且容得下本次蛋种的箱子，已有同类蛋的箱子优先。它必须实际走到箱子所在格，完成产蛋工作后才增加箱内数量；无合适箱子时沿用地面产蛋。每个箱子同时只由一只母鸡或一名收蛋工人预留。

箱内鸡蛋是独立容器中的真实批次，不是地面物品的副本。当前最多容纳 25 枚同类蛋，达到 20 枚时由开启搬运分工的居民自动收取；选择箱子可请求提前清空、取消请求或禁止使用。提前清空仍要求可达的有效仓位、劳动能力和实际工作，不会直接增加仓库物品。

搬运工走到箱边，完成取蛋，再带着实际鸡蛋走向储位。只有部分仓储容量时，先搬可预留的数量，其余保留箱内。箱为空时清除提前清空请求。关闭搬运、征召、禁止箱子、区域限制或仓位失效会中断任务；未取出的蛋留箱内，已取出的蛋保留在手中并服从普通搬运和生活中断规则。

蛋箱面板显示真实数量、孵化/温损或腐败状态、提前清空请求、独立建筑耐久及正在取蛋的工人进度。木箱和同格母鸡具有各自的选择身份；取蛋动作由模拟工作进度驱动。箱内蛋数、受精斑点、禁止标记和施工预览由程序几何生成。

## 容器怎样与其它系统连接

- 箱内受精蛋继续按所在地温度孵化；每枚蛋只生成一只独立幼鸡。空间或动物容量不足时保留尚未孵出的蛋。
- 温度损坏把受精蛋转为新鲜未受精蛋，释放旧取蛋和产蛋目标。转换后没有持续的「损坏」标记，少于自动阈值时不会因此永久获得自动清箱资格。
- 未受精蛋仍会因温度而腐坏。箱子保护内容物免受地面暴露劣化，禁止使用不会冻结时间。
- 库存和财富各计算箱内批次一次；取出不记作新生产，落库后沿用普通仓储、食用、烹饪和贸易机制。
- 主动拆除把半数木料及原有鸡蛋纳入同一次落地事务。附近放不下时保留箱子、原批次和拆除工作，不先删箱或重置孵化数据。
- 火毁/失去支撑后释放占用者并尝试将实物放到合法位置；无合法位置时按实际数量记录损毁，不虚增仓储。家园自动重建沿用普通蓝图和真实材料施工。
- 建造框架、施工失误、完工耐久、修理和财富使用现有系统；箱内孵化与房间温度共用同一模拟时钟。

## 明确的 Web 适配

| 原版静态机制 | 当前 Web 处理 |
|---|---|
| 先在限定 region 搜索，再按已有蛋数和距离评估 | 现有三维导航没有原版 region BFS；在 30 格内按同类蛋数、距离、身份排序，逐个验证路线 |
| 木/金属材料及材料属性 | 第一版只做木箱；20 木、667 基础施工工作量、50 HP，燃烧性沿用 Web 木设施的 0.8 |
| `pathCost=10`、原版 60 TPS | Web 20 TPS 中额外约 4 tick；这是通行成本适配，不是阻挡 |
| 取出工作 120 tick，然后先放地面再拿起 | Web 工作 40 tick 后原子转入手持容器；仅取可预留仓位的数量，余量留箱内，然后正常行走入库 |
| 玩家直接优先指派一次强制清箱工作 | Web 保存可取消的提前清空请求，由正常搬运调度执行，不能据此绕过禁止、能力或仓储条件 |
| 原版 `Pawn_InventoryTracker` 中孵化蛋有 14°C 特例 | Web 目前只有手持 cargo，没有独立背包；手持和蛋箱均使用所在地温度。145 已修正此证据边界 |

因此满地面的正常收蛋可以直接转到工人空手中，不要求先找临时落点；这是显式适配。拆箱与灾害散落仍经过实际落地容量检查。建筑材质变体、原版完整搜索顺序和直接指定搬运者继续待补。
