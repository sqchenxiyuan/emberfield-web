# v46：损毁、自动规划与重新施工

更新：2026-11-05。继续按“玩法与机制优先，数值后调”推进。本轮将建筑损毁后的恢复经营接入现有物流、施工、储存组和存档；原版依据见 [135 静态机制](135-auto-rebuild-mechanisms.md)。

遵守用户暂停程序交互的要求，本轮只做静态分析、无界面模型测试、类型检查、构建和发布字节核对。没有启动或操作原版、Web 页面、预览或截图；不能将模型通过解释为界面或实际游玩已经验收。

## 玩家使用

在“火灾、修理与重建”面板开启“自动重建家园建筑”。新营地和迁移旧档均默认关闭。建筑毁坏时，若定位格在家园范围内、科技允许且原位置仍可合法建造，就生成普通施工蓝图；居民从真实库存搬运材料，再完成施工。

开关只影响之后的损毁：开启不会追补历史废墟，关闭不会取消已有蓝图。蓝图可用现有取消工具删除，已交付材料走原有退料流程。缺料、材料被禁止、人员离开、允许区域不覆盖目标或路径受阻时，继续使用正常施工的等待和重新分配规则。

## 机制连接

| 情况 | v46 行为 |
|---|---|
| 建筑火毁 | 完整损毁事务提交后，才尝试创建新计划；不会免费还原原建筑 |
| 沙袋被弹丸击毁 | 使用相同的开关、家园和合法位置门槛，重新支付材料施工 |
| 家园范围 | 按定位格判断；只覆盖大建筑的一部分不能替代覆盖定位格 |
| 主动拆除、卸下、取消 | 不触发自动重建 |
| 桥毁坏 | 原浅水和桥位允许时重新规划；桥上的家具失去支撑时不留下悬空蓝图 |
| 木楼板毁坏 | 不自动重建，对应原版普通木地板未启用地形自动重建 |
| 货架 | 继承过滤与优先级，毁坏的成员身份由新蓝图接替，继续加入原储存组 |
| 货架上的物品 | 保留独立物品身份和已有散货/坠落规则，不复制进蓝图 |
| 床、工作台、设备 | 新身份、普通新建设置；不恢复旧主人、账单、燃料、电量或旧品质 |
| 普通建筑施工框架 | 从实际收到材料开始存在可损毁的框架；烧毁会损失已交付材料，手中未交付物资保留 |
| 空蓝图、地形施工、重装 | 空蓝图不作燃料；地板/桥施工不套用普通建筑框架燃烧；重装继续使用原打包家具耐久 |
| 受损框架完工 | 成品保留该框架剩余耐久比例，之后由正常修理恢复；完工不免费治好施工中受的伤 |

原版对玩家派系建筑的判断，在当前 Web 中对应现有殖民地建筑集合；目前尚未实现多派系建筑所有权。即时制作点仍沿用其正常放置方式，不虚构材料施工。样式、全材质目录、施工失败及其独立重试路径尚未扩展。

## 多层世界适配

Web 墙占两块体素。已标识的墙上下两块共用底层定位格的损伤记录，任一部分被致命破坏时整墙移除；施工框架耐久比例、灭火和修理也按整墙处理。支撑毁坏涉及居民或动物下落时，先验证落点；没有合法落点则回滚整次破坏，不产生蓝图或材料损失。

只对本次地形/梯段变化附近的施工框架核查支撑，并采用具体建筑的放置或支撑规则。墙内电线和连接既有梯段的梯子不会因为远处建筑毁坏而被误删。原版没有这种两块高的体素墙，也没有本项目的多层坠落算法，这些属于明确的 Web 适配。

普通建筑框架沿用当前 Web 成品的基础耐久四分之一及已有材质可燃性区别。成本、工时、火势、品质分布等仍是待平衡参数；框架继承比例与材料守恒是本轮机制要求，不代表全部原版数值已拟合。

## 保存与迁移

v46 保存 `autoRebuild` 布尔开关和普通框架损伤，不建立第二份隐形重建队列。蓝图、已交付批次和人物携带物均走既有存档结构。当前版本缺少开关或类型错误、框架耐久上限与成品不匹配、旧版本混入新字段均拒绝读取。

v1–45 原档迁移后开关关闭。旧的已标识墙若上下半各有损伤，合并为底层一条记录，保留较低剩余耐久，不重复累加伤害或免费修复；正在修理的任务引用同步迁移，重复占用会释放重新分配。历史未知 `structureKinds=0` 的块不推测成整墙。

在改动世界模型之前，使用原 v45 实现、生成地图、原始开局物资和公开命令冻结了两份原样存档。它们是旧模型生成的检查点，**不是玩家实机或浏览器导出存档**。验证器核对原提交全部模型依赖、重建旧 bundle 的逐字节一致性和存档 SHA，再验证搬料途中、真实施工中途、完工后的迁移及物料账；不要求瞬时路径和任务 owner 逐字不变。

两份未改写 v45 样本均迁移并继续正常建设，每场经过实际施工 20 workTicks 的保存检查点，再累计续行 119 tick 完工；原物资、携带材料、旧建筑身份和木料账保持一致。数值平衡和程序交互仍不属于这些验证的证明范围。

验证器核对冻结记录，不代替重新执行测试。长时食物测试仍要求至少八个游戏日和 90 份真实收获，逐 tick 核对账本，没有修改作物成熟度或注入收获物。GitHub Pages 流水线继续只安装依赖、构建和部署，测试留在本地。

旧档续建验证和 `--local` 核对需要本机保留的旧 bundle、原始存档、日志和构建产物；这些文件位于忽略的 `test-results` 中。只克隆公开仓库可以核对已跟踪文件与冻结清单，不能据哈希补出缺失样本或宣称重新跑过历史场景。

本轮没有原版新实机样本、Web 点击、窄屏、渲染 Worker 或正常游玩手感验证。恢复交互后，需核对开关可发现性、双层墙选择与耐久显示、火灾后的完整恢复经营体验。更完整的战斗建筑破坏、施工失败、建筑样式和特殊建筑设置仍需后续实现。
