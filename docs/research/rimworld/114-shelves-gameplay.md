# 实体货架：多堆仓储、邻接取放与搬装

2026-11-04。玩法与机制优先；成本、耗时、美观和耐久使用 `src/voxel/shelves.ts` 中的暂定配置，后续再调整节奏。原版依据见 [111 静态机制](111-shelf-storage-mechanisms.md)、[112 实机](112-native-shelves-runtime.md)；本篇描述 Web 实现，不将本地夹具测试当成原版证据。

## 玩家操作

在底部建造栏选择「小货架」或「货架」，点击地面规划，R 旋转。工人配送木材、施工后，搬运工作会按筛选和优先级将货物搬入。小货架占一格、容量三堆；大货架占两格、共六堆。各资源的单堆上限保持原样，例如 75 木材的一堆不会变成 225。

点击任一架格，面板顶部显示货架耐久、整架容量、优先级和接纳筛选。同格物资逐堆列出身份、种类和数量；普通物品详情仍可查看。画面按稳定的物品 ID 顺序分层显示各堆，实际模拟坐标仍在原架格，选择不会跳到视觉高度对应的另一楼层。

人物可以穿过货架，从同层四邻的可停位置取放。取用统一覆盖建造/生产取料、搬运、吃饭、护理药物/食物、穿戴/装备、饲养员取饲料及动物觅食。普通任务继续预约具体源堆与数量，不用同格另一堆替换消失的源物。贸易将可接触货架视作储存范围，包括 Home 外的货架。

改筛选不会删除已有货物。不再接纳的物资继续占槽，等待搬到其他合法仓位；没有目的地时原地保留。岩块、打包建筑始终不能上架。小型尸体可以手动允许，默认不接纳；按死亡时冻结的实际体型判断 `< 0.75`，历史尸体缺少成长记录时保守采用物种成年体型。

## 卸下、重装与损毁

「搬移」选择新位置，「卸下」生成原架的独立包装。满架不要求手动清空：原架格最多留下地面能容纳的一堆，其余物品向附近可达地面散开；包装只包含原货架的身份、耐久、朝向及接纳设置，货物不会装进隐藏库存。货架没有品质，不会在重装时生成品质。

主动卸下或拆除在同一次放置规划中安排全部散货与包装/回收材料。全部能落地才提交；空间不足则保留原架及全部物资、等待清理后重试。等待期间食物仍按正常温度老化。

火灾直接烧毁架体时，如果完好的地面没有足够散货空间，保留原格上的物品并记录有上限、可保存的应急散货例外。搬走或消耗到一堆后自动清除记录。库存仍只有普通物品列表，没有另一个“溢出箱”复制数量。失去楼板支撑时继续使用既有坠落规则；无法获得合法着陆位置的物资计入损毁账本。无空间等待与应急散货是 Web 的守恒适配，原版极端拥堵时的同等保证尚未证明。

货架保护环境劣化，与温度腐坏和火灾分别处理：架上食物仍需要冷库，架体和货物仍能燃烧。货架占地以可通行、不可停留的空间进入房间计算，并参与建筑财富。

## 存档与性能边界

存档升级为 v37，新增实体货架、独立包装设置和应急散货记录。旧版本增加空列表，不重生地图或重排物品。保存后继续验证三槽上限、支撑/净空、整架占地、身份、过滤硬规则、安装/打包/规划总量，以及应急散货对应的实际多堆状态。伪装成旧版本的新字段会被拒绝。

真实 v36 回归夹具由已发布 `9e2dc745c5caa820778ecec44249be503cfce679` 对应源码执行普通指令生成，原始字节与来源哈希随 `tests/fixtures/voxel-v36-before-shelves.*` 入库；不是把新版存档改个版本号。保留 v1–v36 的既有迁移测试。

模拟继续使用固定逻辑步和独立渲染。仓位使用已有放置/预约算法，渲染每次快照建立物品层位索引，避免绘制每个模型部件时扫描全部物品。穿架增加了 Web 的移动耗时，但寻路仍是无权 BFS，**没有实现原版加权路径成本的绕行选择**。Web 优先级仍为既有四级，尚未扩成原版完整枚举；储存组联动、更多材质与美术也留待后续。

## 验证方法

本地最终记录：101 个测试文件、1,271 个用例覆盖通过。全量运行 1,269 项直接通过；另两项既有墙体取消/双灶共享目标场景略超 5 秒，随后在单 Worker、无其他验证任务竞争资源时完整复跑这两个文件，32 项全部通过，未改这两项的断言或时间限制。新增货架用例 18 项全部通过。生产构建与 1,169 个文档相对链接检查通过；正常经营为 7 条命令、6 项检查、312 tick；真实 Chrome Worker/main 各 11 项检查、零运行错误，已核对资源字节并目视检查截图。

新增机制用例覆盖小架三堆/大架六堆、混合搬运、正常施工与取餐、过滤后搬走、硬限制、满架搬装保身份/HP/设置、无空间原子等待、火毁应急散货、精确源堆身份、装备/驯养/护理取用与中途重载、穿行后退出、非法存档、真实 v36 迁移和环境保护与腐坏分离。

`scripts/voxel-shelves-campaign-verify.mjs` 从未修改的历史开局存档执行普通命令，逐 tick 核对数量账本与格容量，经过建造、同格多堆、改筛选、带货卸下、保存与重装。控制几何的六堆满架与极端拥堵由机制测试单独验证，正常经营脚本不注入物资或人物状态。

`scripts/voxel-shelves-browser-verify.mjs` 在真实 Chrome 的 Worker/main 两种模式下，通过鼠标、键盘、可见控件及文件选择器验证：选中货架、逐堆信息、无品质、修改优先级、旋转/取消搬装预览、实际卸下、重装后载入、窄布局与旧存档导入。只读桥接检查状态，并核对浏览器实际加载资源与本地构建字节一致；截图另作目视检查。
