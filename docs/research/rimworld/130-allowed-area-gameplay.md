# 130 · 居民允许区域：玩法、实现与验证

2026-11-04，Emberfield 体素模式，存档 v44。先完成分工、区域编辑和任务中断的玩法闭环；通行惩罚、重试间隔、容量等为 Web 暂定参数。

原版依据分列在 [129 机制](129-allowed-area-mechanisms.md)与[131 原版实机](131-native-allowed-area-runtime.md)。本章描述独立 Web 实现，测试通过不等于原版所有行为均已复刻。

## 玩家如何使用

1. 选择居民，在详情的“允许区域”处进入管理；工作面板也可进入。
2. 创建、命名区域，按当前工作层拖动绘制或擦除。切换楼层后继续绘制，多个楼层共用同一个区域身份。
3. 给居民分配区域。工作目标、材料、食物、床位、娱乐与仓储将按个人分配筛选。
4. 修改区域会让不再合法的任务停止并重新安排。已有施工进度、交付材料、随身物资和独立未完成品保持实物所有权。
5. 选择“不限制”或删除区域可解除约束。存档保留区域及个人分配，旧档居民默认不限制。

区域与既有兔子活动范围共用定义。鹿仍由实体圈地与牵绳管理。区域不是家园、仓库或围墙，不会改写地形、发现隐藏资源或直接转移角色。

## 实际规则

| 行为 | 当前实现 |
|---|---|
| 空区域 | 保留分配身份，但活动不受限制；也修正了兔子原先遇空区停住的行为 |
| 采矿、施工、科研、生产 | 筛选任务所在格；区内物体可从区外相邻工作面操作 |
| 取料与未完成品 | 地面来源需要在区内；随身物资不因携带者经过区外而变成非法来源；加工放置点也需合法 |
| 搬运与成品配送 | 同时筛选来源与收纳点；取消配送保留成品，完成次数不重复结算 |
| 吃饭、休息、娱乐 | 选择区内物品、床位和活动目标；没有合适座位或床时，先尝试返回再原地吃饭、睡觉 |
| 清扫、灭火、修理、护理、饲养、看守、交易 | 按执行者筛语义目标与所需材料、床位或收纳点；不把相邻操作站位当作围墙 |
| 动物与病人移动 | 重新检查移动目标；已抬起患者跟随救援者，不因途中坐标在区外被误判为新的区外患者 |
| 牵绳 | 允许途经区外；最终动物收纳格需在允许区域与封闭圈地的交集中，不能仅因路上先进入圈地就提前解绳 |
| 征召、精神状态 | 暂时忽略限制，区域设置仍保留 |
| 手动装备武器 | 作为明确玩家命令允许越区；装备动作结束后恢复限制，可在途中保存继续 |
| 普通未征召移动 | 区外目标给出明确拒绝信息；可通过征召直接控制 |

路径仍使用真实三维连通性。区外格增加路径代价，因此通常偏向区内通路，但连接两个允许地点的路线可以经过区外。区域不能跨越断梯、锁门、深水或实体障碍。

空闲居民会先寻找允许的工作或需求目标，没有可执行目标时返回区域。没有可达落脚点时说明原因并间隔重试，编辑区域或改变通路后重新评估，不瞬移。这一优先顺序是体素适配：只画实体矿点时仍允许邻接采矿；原版 `SeekAllowedArea` 在普通殖民者行为树中的次序单独记录于129章，未声称完全复用原树。

## 中断与持久化

`Pawn.allowedAreaId` 引用既有 `animalAreas` 中的稳定身份。新 `allowedAreaCreate/Rename/Paint/Delete` 命令复用旧 `animalArea*` 管理接口；`pawnAreaAssign` 分配居民。没有第二份可能不同步的区域数据。

区域按当前工作层平面拾取，主线程和 Worker 都使用 `areaPick`。掩码可以画在空中或未探索层；画出的格只代表玩家自己的标记。快照可显示这些标记，地形、资源和探索状态保持原有可见性限制。

区域编辑替换格子数组，按数组身份重建成员集合。寻路没有把区域集合传入囚犯用的硬边界参数。返回目标不可达的短时重试记录只在内存中存在，读档重新评估。

v1–v43 的真实旧档迁移时补 `allowedAreaId:null`，不改变地图或动物已有区域。v44 严格检查引用；把带新字段的存档仅改版本号伪装成旧档会被拒绝。合成旧档测试显式去掉默认新字段，历史档案本身不重写。

正常任务在区域分配或掩码编辑后立即重检；饲养、牵绳、看守与交易还在自身状态机下一模拟 tick 重检，暂停期间不会继续执行旧操作。必要的安全放物、放人不受目标仓位筛选阻止，避免在无合法卸货点时丢失物资或患者。

## 验证与重现

- `tests/voxel-allowed-area.test.ts`：共享别名、空区、跨层隐藏格标记、真实返区、区外通路、路径偏好、无路恢复、邻接采矿、材料筛选、搬运两端、需求选择、途中保存、删除、严格迁移与手动装备例外。
- `tests/voxel-allowed-area-hosts.test.ts`：火灾、修理、俘获、护理运输、饲养、兔子、牵绳与交易的区域衔接。
- `tests/voxel-allowed-area-production.test.ts`：实际未完成品加工在修改区域后的中断、保留与续作。
- `scripts/voxel-allowed-area-campaign-verify.mjs`：从未经编辑的新地图出发，仅用公开命令完成施工区、材料受限、实际取料、途中读档、缩区中断、扩区完工、征召越区与返回；每 tick 核对资源账本。
- `scripts/voxel-allowed-area-browser-verify.mjs`：通过普通可见 UI 在 Worker 和主线程路径创建新地图，绘制不同工作层、分配、导出导入、实际返区、删除，并检查 980px 布局。仅使用只读桥接查询，不注入状态。

本轮最终本地覆盖 **117 文件、1,546 项测试**，未跳过用例。初次并发运行有两项超时、一处旧档新增字段的预期需要更新，以及长收获准备超时；保留初次报告，修正默认字段预期后仅重跑受影响文件，全部通过。没有修改游戏逻辑来绕过旧档检查，也没有放宽长收获的 tick 或产量要求。

长期回归真实运行 **97,025 tick / 8.085 游戏日**，得到90份谷物后继续验证烹饪与进食。新地图区域流程通过10项检查，记录82次公开命令（含一次预期的区外移动拒绝）、4份存档检查点。额外读取上一版5份原始 v43 河流流程存档，哈希与旧记录一致，迁移不改地形、水域、物资或统计。

Worker/main 浏览器各7项检查、各8张截图，零页面错误，加载资源哈希与本地构建一致。截图检查发现并修复地下区域标记被剖切面遮挡的问题，修复后重新构建并重跑两种渲染路径。`npm run build` 通过；现有较大主包提示仍在，不影响构建结果。测试在本地运行，Pages 工作流只安装依赖、构建和部署。

[冻结的本地验收记录](evidence/allowed-area-voxel-validation.json)保留测试清单、重试过程、源码与脚本哈希、页面资源及旧档来源。`node scripts/research/verify-voxel-allowed-area-validation.mjs` 校验仓库中源码与清单；加 `--local` 进一步核对本机原始日志、截图、构建、模型包与旧档。哈希校验不替代重新运行测试，原版证据仍独立列于129/131章。

## 边界

这是现有居民与家畜子系统的允许区域接入，尚无区域反选、自动昼夜换区、危险事件自动换区或完整原版强制命令体系。当前明确实现武器装备例外；不能由此推断所有手动护理、穿衣、交易命令都忽略区域。区域、物流与未完成品容量采用当前 Web 预算，不据此声称原版规模或性能。
